# 血染钟楼说书人信息推荐系统实施设计

版本：1.0  
状态：阶段六 A 离线验证已完成，待真人专家盲测与灰度  
适用项目：CampBoardGameHost Android App  
首期剧本：《暗流涌动》（Trouble Brewing）

## 1. 背景与目标

当前应用能够生成和展示首夜信息，但部分结果来自列表顺序、固定哈希或简单截取。例如，两人信息通常选择第一个合法目标和第一个陪衬，恶魔伪装直接选择前三个不在场镇民。这些结果可能合法，却没有从整局信息结构评估其质量。

本项目将首夜信息生成升级为“说书人信息推荐系统”：

- 规则引擎保证所有推荐合法；
- 候选生成器枚举说书人可作出的合法裁定；
- 评价器从全局信息结构评估候选方案；
- 搜索器寻找多套高质量且有实质差异的方案；
- 新手说书人可以直接采用默认推荐；
- 熟练说书人可以比较、修改并重新评价多个方案；
- 所有推荐必须可解释、可修改、可重现。

系统不预测完整胜率，也不代替说书人的最终判断。

## 2. 第一版范围

### 2.1 支持内容

第一版限定为《暗流涌动》首夜，支持：

- 厨师首夜信息；
- 共情者首夜信息；
- 占卜师红鲱鱼；
- 酒鬼被告知的镇民角色；
- 酒鬼伪装为调查员时获得的展示爪牙与两名候选玩家；
- 恶魔获得的三个安全伪装；
- 温和、平衡、激进三种推荐风格；
- 固定随机种子；
- 推荐理由、风险提示和评分明细；
- 接受推荐、修改裁定、锁定裁定后重新推荐。

### 2.2 后续范围

第二阶段加入：

- 正常洗衣妇；
- 正常图书管理员；
- 正常调查员；
- 间谍逐次登记；
- 隐士逐次登记；
- 确认链检测；
- 更完整的候选世界分析。

第三阶段加入：

- 中毒信息推荐；
- 多夜信息推荐；
- 对局反馈与专家标注数据；
- 不同剧本的独立规则和评价配置。

## 3. 设计原则

1. 合法性与质量评价分离。
2. 真实身份、被告知身份、本次登记和最终展示信息分离。
3. 固定信息的计算结构与说书人登记裁定分离。
4. 严重风险不能被多个小额加分抵消。
5. 默认推荐必须适合新手直接执行。
6. 多个推荐必须在设计意图上存在明显差异。
7. 随机性只用于接近方案的平局处理和结果多样性，不参与合法性。
8. 推荐理由必须直接来自评价明细，不能另写一套无法验证的解释。
9. 推荐引擎必须是纯 Kotlin 代码，不依赖 Compose 或 Android `Context`。

## 4. 规则边界

### 4.1 红鲱鱼

- 必须是实际属于善良阵营的玩家；
- 可以是占卜师本人；
- 不能因为间谍在某次判定中登记为善良，就把间谍设为红鲱鱼；
- 整局固定不变；
- “新手模式尽量不选择占卜师本人”可以作为软偏好，但不能作为官方规则限制。

### 4.2 酒鬼

- 酒鬼的真实角色是外来者“酒鬼”；
- 酒鬼被告知自己是一个镇民；
- 该镇民角色不应作为真实在场角色重复分配；
- 酒鬼没有被告知角色的能力；
- 说书人应按被告知角色的正常流程唤醒或处理酒鬼；
- 酒鬼收到的信息可以为真、为假或部分成立，但必须使用正常信息格式。

因此，“能力是否可靠”和“展示内容是否碰巧为真”必须分别建模。

### 4.3 厨师与共情者

厨师和共情者的信息不能简单定义为只由真实身份决定。若间谍或隐士参与相关检测，本次登记裁定可能改变最终数字。

统一计算流程为：

```text
真实局面
  → 本次能力检测范围
  → 本次登记裁定
  → 醉酒或中毒状态
  → 最终展示信息
```

第一版暂不自动推荐厨师、共情者涉及的间谍或隐士登记，但数据模型必须允许第二阶段加入。

### 4.4 恶魔伪装

- 必须属于当前剧本；
- 必须是善良角色；
- 必须不在场；
- 三个角色不能重复；
- 酒鬼被告知的镇民是否与恶魔伪装重合属于方案质量问题，不应误判为角色真实在场；
- 对新手恶魔应优先推荐容易执行、信息负担较低的伪装。

## 6. 领域模型

### 6.1 游戏局面

```kotlin
data class GameState(
    val script: ScriptId,
    val players: List<PlayerState>,

data class PlayerState(
```

座位号是领域层的稳定标识。玩家姓名只用于展示，不应参与算法排序、随机种子或候选相等判断。

### 6.2 角色定义

```kotlin
data class RoleDefinition(

    val publicVerifiability: Int,

```

元数据是版本化启发式配置，不属于官方规则。配置变更必须可以单独测试和回滚。

### 6.3 登记裁定

```kotlin
data class RegistrationDecision(
    val playerSeat: Int,
    val affectedAbility: RoleId,
    val registeredAlignment: Alignment? = null,
    val registeredType: CharacterType? = null,
    val registeredRole: RoleId? = null,
    val reason: RegistrationReason,

```

登记只对指定能力的本次检测有效，不能修改玩家真实身份，也不能赋予被登记角色的能力。

### 6.4 最终展示信息

```kotlin
data class AbilityObservation(
```

## 7. 候选生成

### 7.1 生成顺序

第一版采用：

1. 构建并验证真实局面；
2. 计算不受说书人选择影响的基础信息；
3. 枚举酒鬼被告知角色；
4. 枚举占卜师红鲱鱼；
5. 枚举恶魔三个伪装；
6. 枚举酒鬼调查员展示角色和两名候选人；
7. 组合为完整方案；
8. 应用硬约束；
9. 分层评价；
10. 选择三套差异化推荐。

### 7.2 硬约束

硬约束失败的方案直接淘汰：

- 所有座位必须存在；
- 两名候选玩家不能重复；
- 红鲱鱼必须实际属于善良阵营；
- 红鲱鱼可以是占卜师；
- 酒鬼被告知角色必须是当前剧本中的镇民；
- 恶魔伪装必须属于当前剧本中的不在场善良角色；
- 三个恶魔伪装不能重复；
- 调查员信息必须展示一个当前剧本中的爪牙角色；
- 酒鬼调查员可以得到不真实的信息，但格式必须合法；
- 同一方案中所有锁定的用户裁定必须被保留。

合法性验证器返回结构化失败原因：

```kotlin
sealed interface LegalityFailure {
    data object MissingSeat : LegalityFailure
    data object DuplicateCandidates : LegalityFailure
    data object EvilRedHerring : LegalityFailure
    data object BluffIsInPlay : LegalityFailure
    data object DuplicateBluffs : LegalityFailure
    data object RoleOutsideScript : LegalityFailure
    data object InvalidShownRoleType : LegalityFailure
}
```

## 8. 分层质量评价

不使用可以任意互相抵消的单一总分。每个方案依次通过以下层级。

### 8.1 第一层：合法性

任何规则错误直接淘汰。合法性不产生奖励分。

### 8.2 第二层：新手安全等级

检测：

- 是否形成近似锁死的确认链；
- 酒鬼信息是否明显到容易立即识别酒鬼；
- 多条强信息是否集中指向同一关键玩家；
- 是否给真实恶魔或爪牙造成过高的首日直接压力；
- 恶魔是否缺少容易执行的伪装；
- 方案解释是否需要复杂登记知识才能理解。

输出等级：

```kotlin
enum class QualityTier {
    RECOMMENDED,
    ACCEPTABLE_WITH_WARNING,
    EXPERT_ONLY,
    REJECTED,
}
```

新手模式只允许返回 `RECOMMENDED`。进阶模式可以显示 `ACCEPTABLE_WITH_WARNING`，但必须展示风险。

### 8.3 第三层：核心质量

核心指标包括：

- 信息涉及座位的分布；
- 是否存在有意义但不过强的交叉验证；
- 是否存在少量合理冲突；
- 是否保留至少两个合理解释方向；
- 酒鬼错误信息是否具有可信度；
- 邪恶阵营是否能够利用推荐伪装推动错误世界；
- 关键角色是否被不必要地公开暴露；
- 方案是否把过多讨论压力集中到一名新手玩家。

第一版可以用启发式实现，但每项必须记录评价明细：

```kotlin
data class ScoreItem(
    val ruleId: String,
    val category: ScoreCategory,
    val delta: Int,
    val messageKey: String,
    val affectedSeats: List<Int> = emptyList(),
)
```

### 8.4 第四层：风格

```kotlin
enum class RecommendationStyle {
    GENTLE,
    BALANCED,
    AGGRESSIVE,
}
```

- 温和：降低强冲突和关键角色暴露；
- 平衡：保留一至两处可讨论交叉，作为默认；
- 激进：允许更多重叠和冲突，但不得违反规则或形成明显锁死。

风格只改变软偏好，不能改变合法性。

## 9. 搜索和多样性

### 9.1 第一版使用穷举

对于第一版的有限决策，优先使用完整枚举：

```text
全部合法候选
  → 分层评价
  → 分风格排序
  → 多样性选择
  → 三套推荐
```

暂不实现束搜索。只有性能基准证明穷举无法满足目标延迟时，才加入束搜索。

### 9.2 结果多样性

不得仅从高分方案中随机抽取三个近似结果。

为每个方案生成 `PlanEffectSignature`，至少包含：

- 红鲱鱼座位；
- 酒鬼被告知角色；
- 酒鬼调查员展示的爪牙；
- 酒鬼调查员候选座位集合；
- 恶魔伪装集合；
- 被保护、被怀疑和被暴露的座位集合；
- 主要支持与冲突关系。

选择下一套方案时，使用：

```text
选择价值 = 方案质量 - 与已选方案的最大相似度惩罚
```

最终优先返回温和、平衡、激进各一套。若某种风格没有合格方案，则返回质量最高且与已有结果差异最大的替代方案。

### 9.3 固定种子

种子只用于：

- 完全同等级方案的稳定平局处理；
- 保证同一局面可以复现；
- 测试多种合法变体。

不能用种子绕过质量排序。

## 10. 推荐解释

界面输出分成三层。

### 10.1 执行步骤

```text
将5号设为占卜师红鲱鱼。
唤醒6号酒鬼调查员。
展示“投毒者”。
指向1号和4号。
向恶魔展示：僧侣、士兵、管家。
```

### 10.2 合法性解释

```text
5号实际属于善良阵营，因此可以成为红鲱鱼。
6号真实身份是酒鬼，因此调查员信息可以不可靠。
僧侣、士兵和管家都属于当前剧本且没有真实在场。
```

### 10.3 推荐理由和风险

```text
推荐理由：
- 酒鬼信息不会直接命中真实爪牙；
- 两名候选分别受到不同首夜信息影响，能形成可讨论冲突；
- 关键角色没有被多条信息同时指向；
- 三个恶魔伪装都适合新手执行。

风险：
- 1号可能承受较高的首日讨论压力。
```

推荐理由必须由 `ScoreItem` 和 `PlanWarning` 转换而来。措辞使用“可能”“倾向于”，避免宣称玩家必然公开信息或采取特定行为。

## 11. 用户交互

### 11.1 新手模式

默认只展示平衡型推荐：

- 执行步骤；
- “采用推荐”；
- “查看其他方案”；
- “修改裁定”。

不默认展示总分、实际身份或复杂登记细节。

### 11.2 进阶模式

展示三套方案及：

- 风格标签；
- 执行步骤；
- 推荐理由；
- 风险提示；
- 与当前方案的差异；
- 可展开的评价明细；
- 采用、修改和重新评价入口。

### 11.3 修改与重新推荐

用户修改一项裁定后，该裁定进入锁定状态。重新推荐时：

1. 验证锁定裁定是否合法；
2. 保留所有锁定裁定；
3. 只枚举未锁定决策；
4. 对新方案重新进行全局评价；
5. 输出新的三套差异化方案。

## 12. 测试策略

### 12.1 规则测试

- 红鲱鱼不能是爪牙或恶魔；
- 红鲱鱼可以是占卜师本人；
- 酒鬼被告知角色必须为镇民；
- 酒鬼信息可以语义为真或假；
- 恶魔伪装必须属于当前剧本；
- 恶魔伪装必须不在场且互不重复；
- 两名候选玩家不能重复；
- 厨师环形相邻计算正确；
- 共情者左右存活邻居计算正确。

### 12.2 评价测试

- 三条信息集中于同一座位的方案低于分散方案；
- 强确认链方案被降级；
- 酒鬼信息明显自证错误的方案低于可信错误信息；
- 没有可执行恶魔伪装的方案被降级；
- 平衡型方案优先包含少量交叉而非完全独立；
- 激进型可以比温和型有更多冲突，但不得越过安全底线。

### 12.3 搜索测试

- 所有输出都通过独立合法性验证；
- 相同局面和种子输出一致；
- 不同种子只影响同等级方案的平局结果；
- 三套推荐达到最低差异阈值；
- 锁定用户裁定后不会被搜索器修改。

### 12.4 黄金局面

采用八人示例：

```text
1号：厨师
2号：共情者
3号：占卜师
4号：送葬者
5号：圣女
6号：酒鬼，被告知为调查员
7号：猩红女巫
8号：小恶魔
```

测试要求：

- 厨师结果为1；
- 共情者结果为0；
- 平衡型推荐不得直接用酒鬼信息命中7号或8号；
- 至少一套推荐形成可解释但不锁死的冲突；
- 三套方案不能只改变候选玩家顺序；
- 不断言唯一最高分，除非固定全部配置和种子。

## 13. 质量验证

第一版不以单局胜率作为主要评价指标。胜负受到玩家经验、发言和随机决策影响，不能直接反映推荐质量。

离线评估采用：

- 非法推荐率；
- 固定种子复现率；
- 专家对新旧算法方案的盲测偏好率；
- 推荐前三名中存在可直接使用方案的比例；
- 推荐理由正确率；
- 三套推荐的差异度。

产品反馈采用：

- 默认推荐采用率；
- 修改率；
- 最常修改的裁定类型；
- 修改原因标签；
- 新手与进阶用户采用率差异。

验收底线：

- 非法推荐率为0；
- 固定种子复现率为100%；

## 18. 第二阶段：中毒信息与登记裁定（2026-07-19）

本阶段合并处理两个问题：能力不可靠时如何选择高质量信息，以及间谍、隐士参与检测时如何裁定登记。

### 18.1 已确认的问题

1. 旧的数字假信息逻辑会强制排除真值，只返回首尾两个错误数字。这会把“中毒或醉酒可以获得任意信息”错误实现成“必须获得假信息”，并且极端数字容易给善良阵营造成不必要的过高压力。
2. 旧逻辑没有利用上一晚已经展示的信息，连续多夜可能出现缺乏叙事理由的大幅跳变。
3. 投毒者效果在夜晚结束时立即清除，导致本应持续到次日白天的中毒失效。
4. 中毒共情者仍会先进入间谍或隐士登记裁定，再从该结果生成假数字；这把两个本应独立的说书人决定错误地耦合在一起。
5. 厨师、共情者只检测阵营，但旧界面仍要求为间谍选择一个具体善良角色，增加了无意义操作。
6. 间谍按真实身份登记时没有留下事件记录，复盘只能看到“登记善良”的特殊情况。
7. 共情者邻座有间谍时，界面没有预览“按真实邪恶登记”和“登记善良”分别会得到什么数字。

### 18.2 已实施的修改

- 新增通用不可靠数字推荐器，输出稳健、平衡、激进三档建议；候选包含真值，且激进高压结果带警告。
- 推荐器读取该角色此前实际展示的不可靠数字，为稳健和平衡方案加入历史连续性评价。
- 厨师、共情者和钟表匠复用同一套纯 Kotlin 推荐逻辑；厨师和共情者额外计算高数字造成的压力成本。
- 中毒效果改为持续经过次日白天，在下一夜开始前过期；如果投毒者夜间死亡，则在天亮时终止。
- 所有不可靠角色统一跳过间谍、隐士登记面板，直接选择最终展示信息；不可靠信息与登记裁定不再互相限制。
- 厨师和共情者的间谍登记改为“仅阵营”维度，不再要求选择具体角色。
- 可靠共情者邻座有间谍时显示两个结果预览；厨师也显示对应的相邻对数预览。
- 间谍无论选择真实邪恶身份、登记善良，或因中毒不能改登记，都会写入说书人事件记录。
- 间谍登记按钮增加明确的当前选中状态。

### 18.3 规则边界

- “不可靠”意味着信息可以为真，也可以为假，不意味着角色可以不被正常唤醒。
- 不可靠信息直接裁定最终展示内容；不应先决定间谍或隐士登记，再把那个结果当成必须避开的真值。
- 可靠能力仍先完成本次交互的登记裁定，再由规则计算最终信息。
- 只检测善恶阵营的能力使用阵营登记；需要得知具体角色的能力才要求角色登记。
- 登记是按每次交互裁定，不应成为整局永久状态。

### 18.4 测试与验收

- 单元测试覆盖：真值仍可推荐、三种风格有实质差异、历史连续性生效、非法范围被拒绝。
- 单元测试覆盖：中毒经过次日白天仍有效、投毒者死亡时终止、下一夜开始前过期。
- 手工场景一：中毒共情者邻座有间谍，进入共情者步骤时不出现登记面板，直接出现三档数字建议。
- 手工场景二：可靠共情者邻座有间谍，选择“真实身份/登记善良”时，结果预览和最终数字同步变化。
- 手工场景三：间谍参与厨师检测时只选择阵营登记，不出现具体角色列表。
- 手工场景四：夜间给角色投毒，进入次日白天后验证处女、杀手等白天能力仍受中毒影响；进入下一夜后旧目标清除。

## 19. 第二阶段补充：非数字不可靠信息（2026-07-19）

### 19.1 修复范围

以下角色此前虽然显示“能力不可靠”提示，但界面仍可能只能展示规则真值。本轮已补齐最终信息选择：

- 占卜师：在“有/没有”两个合法结果中推荐；二元结果只有两个不同选项，不伪造第三个重复方案。
- 侍女：复用不可靠数字推荐器，输出稳健、平衡、激进数字，并保留本次查询座位。
- 送葬者：从当前剧本角色中推荐最终展示角色。
- 守鸦人：选择查询目标后，从当前剧本角色中推荐最终展示角色。
- 贤者：从合法玩家对中推荐“恶魔在这两人之一”的最终展示组合。

### 19.2 推荐原则

- 稳健方案优先保留真信息；中毒或醉酒并不强制说书人撒谎。
- 平衡方案优先有限误导，避免直接制造最高压力。
- 激进方案优先更强误导，并在压力达到阈值时显示警告。
- 所有方案先保证输出格式符合原角色能力，再评价是否真实和误导压力。
- 是非信息只有两个不同结果，因此只展示两个不重复的合法建议。
- 可靠角色仍直接展示规则计算结果，不经过任意信息推荐器。
- 能力不可靠时，查询所涉及的间谍或隐士登记不再限制最终信息。

### 19.3 回归验收

- 中毒占卜师选择完两名玩家后，不能再通过原按钮直接展示真值，必须从“有/没有”建议中选择。
- 中毒侍女选择完两名玩家后显示三档数字建议，下一夜历史连续性不会误读查询座位。
- 中毒送葬者显示三档角色建议；可靠送葬者仍显示被处决玩家按本次登记计算的角色。
- 中毒守鸦人选择目标后显示三档角色建议；可靠守鸦人仍显示目标的规则角色。
- 中毒贤者显示三档玩家对建议；可靠贤者的两人中始终包含恶魔。

## 20. 第三阶段：可靠二选一信息联合推荐（2026-07-19）

### 20.1 覆盖角色

- 洗衣妇；
- 图书管理员；
- 调查员。

这三个角色的可靠信息不再只使用“第一个合法目标 + 第一个陪衬”。推荐器将以下内容作为不可分割的完整方案：

```text
展示角色 + 真正满足信息的玩家 + 陪衬玩家 + 本次间谍/隐士登记
```

### 20.2 合法候选生成

- 洗衣妇：真实镇民；或让能力正常的间谍在本次交互登记为当前剧本内的某个镇民。
- 图书管理员：真实外来者；没有外来者时允许“没有外来者”；或让能力正常的间谍登记为当前剧本内的某个外来者。
- 调查员：真实爪牙，包括按真实身份登记的间谍；或让能力正常的隐士登记为当前剧本内的某个爪牙。
- 陪衬不能是信息角色本人，也不能与真正目标相同。
- 间谍或隐士中毒时，不生成依赖其错误登记的候选。
- 酒鬼或中毒的信息角色继续进入任意信息推荐流程，不使用可靠联合候选。

### 20.3 评分与界面

- 稳健：优先正常登记、较低角色暴露和较低信息压力。
- 平衡：优先具有讨论价值但不会立即形成硬确认的组合；作为新手默认按钮。
- 激进：提高特殊登记和高压组合权重，并显示登记或压力警告。
- 选择推荐后，同时应用展示信息和本次特殊登记，立即写入登记事件。
- 保留“使用上方手动裁定”，熟练说书人可以继续手动选择登记并展示当前规则结果。

### 20.4 验收场景

- 洗衣妇 + 间谍：至少存在正常镇民方案；间谍可登记时，激进候选可以包含“间谍登记为镇民”。
- 图书管理员 + 无外来者 + 间谍：稳健方案可推荐“没有外来者”，其他方案可让间谍登记为外来者。
- 调查员 + 隐士：隐士能力正常时可生成登记为具体爪牙的方案；隐士中毒时该类方案消失。
- 采用特殊登记方案后，玩家展示卡、登记面板和事件记录中的角色必须一致。
- 信息角色自身中毒时，不显示可靠联合推荐，改为原有不可靠信息选项。

## 21. 第四阶段：不可靠二选一评分与历史压力（2026-07-19）

### 21.1 替换固定哈希

酒鬼或中毒的洗衣妇、图书管理员、调查员不再通过固定字符串哈希生成两个假选项。新流程为：

1. 从当前剧本取得能力允许展示的角色类型；
2. 穷举除信息角色本人外的玩家组合；
3. 图书管理员与调查员额外加入“没有外来者/没有爪牙”；
4. 判断候选在实际身份下是否恰好为真；
5. 计算角色暴露、讨论价值、误导压力和历史重复指向；
6. 输出稳健、平衡、激进三套不同方案。

### 21.2 历史压力

- 每次真正展示信息时，从展示副标题和说明中提取涉及的座位。
- 事件记录除信息接收者外，也保存被信息指向的玩家。
- 后续推荐统计每名玩家此前被可靠或不可靠信息指向的次数。
- 稳健与平衡方案惩罚重复集中，激进方案允许有意识地继续施压并显示警告。
- 旧存档没有结构化目标名称时保持兼容，只是不计入此前缺失的历史压力。

### 21.3 风格含义

- 稳健：明显偏好真实信息、低暴露玩家和未被反复指向的组合。
- 平衡：允许有限假信息，优先新鲜且有讨论价值的组合。
- 激进：提高强假信息和压力叠加权重，交由熟练说书人判断。
- 真信息始终保留为合法候选；能力不可靠不等于必须撒谎。

### 21.4 验收场景

- 中毒洗衣妇、图书管理员、调查员均显示带风格标签的推荐，不再出现“展示选项 A/B”。
- 连续两条信息指向同一玩家后，新一条平衡推荐应优先选择其他质量相近的玩家。
- 激进方案仍可重复指向已有压力的玩家，但应显示高压警告。
- 中毒图书管理员可以推荐“没有外来者”；中毒调查员可以推荐“没有爪牙”。
- 展示后在事件记录中可以看到信息接收者和被指向玩家均被关联。
