# PROD-GLOBAL-3E — Generic Whole-Game Strategic Continuation

> 2026-10-12 — experimental first acceptance seam, NOT yet a live AI recommendation or automatic action/observation publisher. Stacked Draft PR #304. The product-owner's latest policy is **all roles / all consequential events / all future nights**. The earlier first-night Poisoner/FT gate only verifies a limited legal observation domain and is not the strategic planning controller.

## What is implemented

- `HostOpeningSemanticGateV2` retains bounded, typed `HostOpeningStrategyMemoryV2` after initial full-board Host acceptance. This is **defeasible advisory strategy**, neither a canonical Host fact nor hidden model reasoning.
- `StorytellerStrategicContinuationV2.encode` takes an immutable `ClocktowerSessionState`, prior `HostOpeningSemanticAcceptanceV2`, and **caller-provided Host-verified current open decision inventory**; reads the existing `StorytellerProviderHistoryPrefixMaterializerV1.captureLive`. The request contains current actual and displayed roles, life/poison status, recorded player experience and **claims labelled as claims**, typed chronological action/observation entries with phase/round/exclusive cutoff, history coverage flags, prior opening and prior multi-night tensions/intentions/uncertainties. No candidate menu or role-specific trigger.
- `PersonalDirectOpenAiV1` now routes the continuation schema and expert cross-night prompt through the existing personal Responses API (store:false). `StorytellerStrategicContinuationV2.recommend` can make ONE explicit follow-up request on a captured Host session and rejects a result if the live session identity changed during the call.
- Host verifies exact session revisions/global chronology, one KEEP/REVISE/RETIRE verdict per prior intention, bounded updated strategy memory, and `affectedOpenDecisionIds` **subset of the supplied currently open IDs**. Nothing in the continuation output can publish a clue, change a registration witness, rewrite a prior observation, create a game action, or override Drunk automatically.
- The request is a strategic checkpoint. No dedicated Poisoner, Drunk, Fortune Teller, Mayor or other strategist is introduced. Real role-specific legal-domain producers remain with Host.
- Tests use an actual GLOBAL_V1 `ClocktowerGameSession` with confirmed action, published typed observation and user-entered claim; reject stale chronology, fabricated IDs, duplicate/missing intention revisions; exercise a changed alive state under the **same** generic request contract. Exact GitHub CI/R2 and real Luna strategic-quality review still required.

## Crucial limitations before this can drive a playable game

1. **Real Host open-decision inventory & generic material-change signal.** The current `OpenDecision` list is supplied by the Host caller; there is not yet a tested universal generator for later-night legal decisions, nor a persistent operator-decision/claims timeline with complete coverage. Do not claim `captureLive` is a complete game history: its coverage flags explicitly say PARTIAL/UNKNOWN. The typed `toString()` textual payload is evidence from real typed records, but is not the final structured observation codec; improve without inventing unknown facts.
2. **Revision-triggering semantics.** On any material verified Host/Storyteller change, compare the new current prefix and accepted prior strategy. Avoid unnecessary paid calls when irrelevant; no trigger based only on one named event. Manual Drunk override belongs to Host's setup record and must cause a **whole-plan** check, not an independent Drunk request.
3. **Remaining legal candidate authority.** A strategic checkpoint does NOT itself choose current legal options. Later implement one Host-validated **whole remaining plan** request that uses updated memory and actual causal prefix, preserves frozen player-visible observations, validates source revision and the entire coupled result against current Host domains before optional auto/manual adoption.
4. **Production integration and memory.** Existing live `requestLiveGlobalAdvice` still runs pointwise V1 decisions in some modes. Converge these consumers on one generic continuation, version the game-scoped latest strategy and discard asynchronous callbacks on game/revision changes. Keep recovery effort proportional to interruption-resume-only requirement; no backwards compatibility required.
5. **Quality and E2E.** Compare initial vs updated multi-night coherent plans with multiple configurations/roles, poison, death, claims and Storyteller overrides. Check alternatives, consistency, honest unknowns, fair information ecology and model latency. CI/R2 alone is NOT Luna strategy acceptance. App/phone tests and superseded code removal remain blocked until production parity.

**Next:** atomic Host transition observer + evidence-type-preserving residual selection scope, then wire this continuation protocol to real production strategy state and independent Luna blind tests. Do not construct another role/event-specific route.
