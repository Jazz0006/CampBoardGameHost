## Product invariant
One expert AI follows its own defeasible multi-night strategic memory across ANY role and meaningful Host-confirmed change. Never have separate Drunk/Poisoner/Empath/Fortune Teller model planners. A rule producer may be role-dependent; triggering/replanning must not be. Existing player-received observations, committed actions and legal Host rulings stay immutable; uncertain player claims do not become true identities.

## Implemented in this slice
- `StorytellerStrategicChangeCheckpointV2`: captures immutable actual `ClocktowerSessionState` plus current real phase/round. Compares committed mechanical GameState, confirmed action timeline, published observation log, player level/claim inputs, confirmed Storyteller decision archive, and real game position generically. **No substantive change = no new model request** even if a revision counter increments. If a state/position change is not accompanied by an advancing Host revision/global chronology, fail closed as `HOST_REVISION_REQUIRED`; no model action based on a pure UI draft/navigation change.
- Historical action and received-observation lists must be append-only. Past decision events and explicit corrections must also remain prefix-stable. Stale or wrong-game snapshots and response revisions cannot advance memory.
- `HostCurrentOpenDecisionInventoryV2` converts ONLY present, Host-generated `StorytellerProviderRequestV1` pending decisions into source-verified IDs. The request must exactly match the current game/script/revisions; first-night information must be in that phase and cannot be re-opened after the original player observation was recorded. Distinguish `NIGHT_INFORMATION` from other currently pending rulings, but **no role-specific planner**. This is a bounded *current pending* inventory, NOT an invented full future decision list.
- `StorytellerStrategicContinuationV2.encode` also includes explicit, **unsequenced** CONFIRMED/APPLIED Storyteller decision-history data and typed correction references, labeled as UNKNOWN relative to canonical global action/observation chronology. Does not materialize a unique Spy/Recluse witness or treat merely PROPOSED choices as fact. The regular action/observation history still has its exact global prefix and truthful coverage flags.
- Production UI: after accepted V2 whole-opening and actual game setup commit, captures immutable strategic checkpoint and versioned memory cursor. When an AI-assisted pending Host decision materializes, the generic checkpoint audits material changes and writes only a small `STRATEGIC_HOST_REVIEW_REQUIRED` or rejection diagnostic event; no *additional paid model request* or automatic clue is performed by this slice. This is a **shadow production observer**, not the completed dynamic planning feature.
- Tests: real GLOBAL_V1 Session with confirmed action, player claim, mechanical death, published private information, raw revision-only update, provisional UI-only position, stale/duplicate provider scope, immutable published observation, stale prior response and cursor. These are mechanics/contract tests; not semantic multi-night quality tests.
