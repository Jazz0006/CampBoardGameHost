# 自动说书人 V4 阶段 0 基线报告

> 采集日期：2026-08-06  
> 基线分支：`codex/storyteller-algorithm-v4`  
> 基线起点：`6a6cf9e`（V4 文档提交，尚未实施 V4 生产代码）  
> 样本量：每项 1000 局  
> 用途：记录旧算法行为，供后续 PR 做配对比较；本报告不把已知缺陷定义为正确行为。

## 1. 采集方法

基线由测试专用 `StorytellerV4BaselineSimulator` 使用固定种子集采集。相同种子集重复执行必须生成完全一致的报告。

初始线索使用紧凑的 8 人《暗流涌动》场景：

- 在场角色：厨师、共情者、占卜师、送葬者、圣女、酒鬼、猩红女巫、小恶魔；
- 酒鬼初始显示为调查员；
- 可用的不在场镇民：调查员、僧侣、士兵；
- 完整初始模板包含红鲱鱼、酒鬼显示角色、必要的酒鬼调查员信息以及三项恶魔伪装；
- 每局只改变 `GameState.seed`，其余状态保持一致，以观察旧选择器是否真正使用跨局种子产生多样性；
- 每个选中方案都再次通过 `PlanLegalityValidator` 验证。

动态数字使用以下固定场景：

- 信息状态：中毒；
- 推荐风格：平衡；
- 真实值：0；
- 合法范围：0–2；
- 每点压力成本：2；
- 通过 `UnreliableNumberInformationRecommender` 生成候选，再由 `AutomaticInformationPolicy` 做最终选择；
- 每次决策使用不同但稳定的事件键。

## 3. 基线结论

本次基线与 V4 的问题诊断一致：

1. `PlanEvaluator` 将非调查员的酒鬼显示角色降级，使调查员垄断最高质量等级。
2. `RecommendationSearch` 只有在质量等级和分数完全相同时才使用旧式种子打破平局；在本场景中，跨局种子没有改变最终完整模板。
3. 动态数字的真假分组存在跨事件变化，但同一假信息分组内仍形成固定结果映射。
4. 当前选中方案均合法，因此后续改造的重点是多样性、建模、可复现性和审计能力，而不是用随机掩盖非法候选。

## 4. 后续比较要求

后续 PR 至少应在相同固定种子集上报告：

- 酒鬼显示调查员比例及各合法显示角色分布；
- 完整初始模板数量、相邻重复率和最长连续重复；
- 动态数字 0、1、2 的分布；
- 同一决策重放一致率；
- 非法候选或非法选中方案数量。

阶段 0 只记录旧行为，不为上述 100% 集中或固定映射添加永久回归断言。

## 5. 关键规则文本审计

阶段 0 对 V4 近期会触及的四个《暗流涌动》角色进行了官方规则页核对：

| 角色 | 官方规则要点 | 当前应用文本 | 结论 |
|---|---|---|---|
| 图书管理员 | 开局得知两名玩家之一是某个外来者，或得知没有外来者 | 含上述两种结果 | 一致 |
| 调查员 | 开局得知两名玩家之一是某个具体爪牙 | 额外写有“或得知没有爪牙” | 不一致；不得将该额外分支固化为正确回归行为 |
| 隐士 | 可能登记为邪恶、爪牙或恶魔，即使已死亡 | 表达相同 | 一致 |
| 间谍 | 每晚查看魔典；可能登记为善良、镇民或外来者，即使已死亡 | 表达相同 | 一致 |

官方核对来源：

- [Librarian](https://wiki.bloodontheclocktower.com/Librarian)
- [Investigator](https://wiki.bloodontheclocktower.com/Investigator)
- [Recluse](https://wiki.bloodontheclocktower.com/Recluse)

本阶段只记录调查员文本差异，不在基线提交中顺带修改 UI。该文本应在建立 PR 1 的规则知识边界时修正，并由带版本和来源的规则资源接管，避免继续把角色事实散落在 `MainActivity`。

## 6. PR 2a 配对复测

PR 2a 删除了非调查员酒鬼显示角色的 `ACCEPTABLE_WITH_WARNING` 强制降级，并增加回归测试确认洗衣妇、图书管理员和僧侣均可保持 `RECOMMENDED`。

在相同 1000 个固定种子上复测：

| 指标 | 阶段 0 旧算法 | PR 2a 后 |
|---|---:|---:|
| 调查员进入 `RECOMMENDED` | 是 | 是 |
| 多个非调查员角色进入 `RECOMMENDED` | 否 | 是 |
| 最终选择调查员 | 1000 / 1000 | 1000 / 1000 |
| 不同完整模板数 | 1 | 1 |
| 相邻模板重复率 | 100.0% | 100.0% |
| 非法选中方案 | 0 | 0 |

结论：PR 2a 已消除质量等级层面的结构性排除，但现有 `RecommendationSearch` 仍按总分确定性取最高结果，因此最终分布尚未改变。该剩余问题不得在热修复中临时加入随机补丁，应按 V4 的 PR 4 和 PR 5 由分数容差池、候选家族预算和稳定加权选择统一解决。
