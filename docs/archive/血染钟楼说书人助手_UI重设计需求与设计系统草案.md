# 血染钟楼说书人助手
## UI 重设计需求与设计系统草案

**版本：0.1｜2026年7月**

> 产品定位：高级、神秘、克制的夜间主持工具。血染钟楼的氛围应服务于主持效率，而不是压过信息本身。

## 执行摘要

当前产品已经完成第一轮实际测试，核心流程基本可用。下一阶段的目标不是继续零散美化，而是将它升级为具有统一设计语言、完整反馈机制和稳定操作体验的商业级产品界面。

核心方法：先冻结功能基准，完成界面审计，再建立设计系统和组件展示页；首先重做夜间行动、玩家状态和首页三个关键页面，验证后逐步推广到全部流程。

## 1. 项目背景与产品目标

### 1.1 产品目标

- 让说书人在三秒内识别当前阶段、当前玩家和下一步操作。
- 在昏暗环境、单手持机、边走动边主持的情况下仍然易读、易点。
- 通过统一组件、字体、间距和状态反馈，消除个人网页项目的视觉痕迹。
- 使用克制的钟楼、月光、黄铜和暗红元素建立品牌辨识度。
- 确保意外刷新、切换应用、锁屏和掉线后能够恢复当前游戏状态。

### 1.2 非目标

- 本阶段不重写后端。
- 不大规模增加玩法。
- 不在视觉重构过程中改变已验证的业务规则、数据结构和流程。
- 不追求长动画或炫技效果。

## 2. 核心使用场景与约束

| 场景 | 设计影响 |
|---|---|
| 昏暗房间主持 | 高对比文字，避免纯黑与纯白刺眼 |
| 边走边操作 | 主按钮固定底部，触控区域足够大 |
| 玩家围坐旁边 | 敏感内容集中显示，避免长期暴露身份 |
| 流程紧张、步骤多 | 当前步骤和下一步持续清楚 |
| 无网络或信号差 | 核心流程离线可用，状态可恢复 |
| 多种手机尺寸 | 动态文字与按钮必须使用 HTML/CSS |

## 3. 设计原则

1. **效率优先**：气氛不能降低可读性。
2. **一个页面一个主任务**：每页只有一个最突出按钮。
3. **状态始终可见**：第几夜、当前玩家、进度清楚。
4. **一致而非花哨**：相同组件使用相同规范。
5. **错误可恢复**：允许返回、撤销、恢复和查看记录。
6. **不只靠颜色**：状态同时使用图标、文字或纹理。
7. **渐进呈现**：复杂设置只在需要时出现。

## 4. 视觉方向

推荐采用“暗黑黄铜剧院”：

- 深黑、炭灰、深蓝黑：操作背景。
- 暗红：邪恶、危险、处决和错误。
- 黄铜金：品牌、主操作、当前步骤。
- 象牙白：正文。
- 钟楼、圆月、黄铜徽章：主要出现在首页、启动和游戏结束页。
- 普通操作页保持克制，避免厚重装饰。

## 5. 设计系统草案

### 5.1 色彩

| 用途 | 建议值 |
|---|---|
| 页面背景 | `#0B0D10` |
| 一级表面 | `#14171C` |
| 二级表面 | `#1B1F25` |
| 主要文字 | `#F1EADC` |
| 次要文字 | `#AAA397` |
| 黄铜金 | `#C5A56A` |
| 暗红 | `#9C3035` |
| 绿色 | `#5D8B72` |
| 蓝灰信息色 | `#61798A` |

### 5.2 字体层级

- Display：28–34 px
- Page title：22–26 px
- Section title：18–20 px
- Body：16–18 px
- Meta：13–14 px

标题可使用具有气氛的衬线字体；正文、按钮和系统信息使用清晰的无衬线字体。

### 5.3 尺寸

- 基础间距：4 / 8 / 12 / 16 / 24 / 32 px
- 页面左右边距：16 px
- 卡片圆角：14–18 px
- 主按钮高度：至少 52 px
- 最小触控区域：44 × 44 px，优先 48 × 48 px
- 动效：150–250 ms

## 6. 核心组件规范

### 6.1 按钮

- Primary：继续、确认、开始夜晚；每页最多一个。
- Secondary：返回、查看详情、稍后处理。
- Text：取消、跳过、帮助。
- Danger：结束游戏、处决、清空数据；必须二次确认。

### 6.2 玩家卡片

- 玩家编号和姓名是第一视觉层级。
- 身份只在需要时显示。
- 存活、死亡、中毒、醉酒、保护使用“图标 + 文本 + 颜色”。
- 已完成夜间行动必须有明确标记。

### 6.3 夜间行动面板

- 顶部显示第几夜、当前步骤、总步骤。
- 中部突出玩家编号、角色和本步目标。
- 指令尽量只有一句，详细规则折叠。
- 底部固定“上一步 / 确认并继续”。
- 跳过必须留下记录，可在夜间总结中复核。

## 7. 关键页面规范

1. **首页 / 恢复游戏**：品牌感、继续上次游戏、创建新游戏。
2. **游戏配置**：玩家 → 剧本 → 角色配置 → 确认，允许返回不丢数据。
3. **夜间行动**：核心页面，尽量无滚动，所有关键信息单屏完成。
4. **白天玩家状态**：快速看到生死、投票权和临时状态。
5. **提名与处决**：明确区分提名、投票、达到门槛和处决结果。
6. **夜间总结**：列出完成、跳过和冲突步骤。
7. **异常恢复**：显示游戏、当前阶段、最后保存时间和恢复入口。
8. **游戏结束**：可使用较强仪式感，显示获胜阵营和关键事件。

## 8. 隐私与防泄密

- 敏感身份默认不在全局列表展开。
- 夜间内容集中在屏幕中央，方便遮挡。
- 切到后台后可自动显示中性遮罩。
- 从最近任务切回时不要直接闪现身份。
- 恢复页面只显示必要信息。

## 9. 素材与实现边界

**适合图片：** Logo、首页背景、钟楼/月亮、圆形徽章、极淡纹理、游戏结束插画。

**必须使用 HTML/CSS：** 按钮、卡片、输入框、弹窗、玩家列表、状态标签、导航和所有动态文字。

原则：图片负责品牌气氛，CSS 负责功能界面。

## 10. 分阶段实施工作流

| 阶段 | 工作 | 交付物 |
|---|---|---|
| P0 功能冻结 | 保存稳定版本和 Git 标签 | 可回退基线 |
| P1 界面审计 | 截取全部页面并记录问题 | UI 审计清单 |
| P2 视觉方向 | 制作 2–3 张方向样板 | 选定方向 |
| P3 设计系统 | 建立设计变量 | `design-tokens.css` |
| P4 组件展示页 | 集中展示所有组件和状态 | `ui-showcase.html` |
| P5 核心页面 | 夜间行动、玩家状态、首页 | 三页原型 |
| P6 全流程推广 | 应用到所有页面 | 统一版本 |
| P7 异常与恢复 | 补全恢复、错误、空状态 | 可靠性版本 |
| P8 第二轮实测 | 完成真实一整局测试 | 测试报告 |

建议页面顺序：夜间行动 → 玩家状态 → 首页/恢复 → 游戏配置 → 提名处决 → 夜间总结 → 游戏结束。

## 11. Codex 协作规范

不要使用“把整个网页改得像商业软件”这种任务。每次只改一个层次或一个页面。

每个任务必须明确：

- 允许修改的文件和组件。
- 不允许修改的业务逻辑、数据结构、元素 ID 和事件。
- 验收视口和检查流程。
- 完成后说明改动、逻辑影响和回退方式。
- 运行现有测试和基本流程检查。

推荐 Git 方式：

```bash
git tag storyteller-v1-functional
git switch -c ui-redesign-v2

git commit -m "ui: add design tokens"
git commit -m "ui: add component showcase"
git commit -m "ui: redesign night action screen"
```

## 12. 验收标准

### 视觉一致性

- 只使用设计系统中的颜色、字号、圆角和间距。
- 每页只有一个最突出主操作。
- 同类组件在所有页面一致。
- 中文和英文内容均不截断。

### 操作效率

- 三秒内判断下一步。
- 主按钮始终可见。
- 危险操作不会与主按钮混淆。
- 完成、跳过、返回和错误都有即时反馈。

### 实际环境

- 最低亮度可读。
- 单手和走动操作不易误触。
- 玩家不容易看到敏感信息。
- 无网络可用。
- iPhone Safari 和 Android Chrome 表现一致。
- 锁屏、切换应用和刷新后能够恢复。
