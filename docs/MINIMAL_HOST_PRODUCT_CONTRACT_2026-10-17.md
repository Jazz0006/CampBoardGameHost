# 最小 Host 事实合同（2026-10-18 修订）

**2026-10-19 晚间最新架构决定（覆盖此前“Host 不计算结果／旧 Rules 全删后才重建”的结论）：当前仍只有最小 Host + 现有 AI 两项业务职责，但 Host 必须按当前剧本、唯一 Session GameState、已确认行动与事件执行**一切规则唯一确定的结果**。凡真正有合法裁量空间，才交 AI/说书人；规则确定的夜间角色顺序、生死/保护/跳过、健康且无特殊登记歧义的信息都由 Host 自动执行。删除旧 Rules 的范围是通用候选域、重复计算、世界枚举、影子对象、过度抽象和旧否决门禁，**不是删除游戏确定性规则本身**；先审计过往误删再实施新批。现有 AI 全链保留，两内置剧本继续可用；动态自定义剧本仍是可选未来目标。详见 HOST_RULES_AI_REBUILD_AND_SOURCE_PURGE_2026-10-18.md。

## Host Core

拥有一局游戏唯一可写状态与顺序事件：对局/座位、真实与展示身份、角色状态、生死、阶段、初始配置、选定酒鬼、玩家行动、说书人真实决定和实际告知玩家的信息、提名投票/处决、状态变更、阶段推进。事件只记录最终确认发生了什么，不区分 AI 采纳还是人工覆盖；不能凭显示结果推断未明确选择的登记事实。

Host 负责：①基础安全、身份、顺序、权限、原子/幂等及过期请求检查；②**规则唯一结果**的本地计算、即时提交与后续步骤推进（不能将“恶魔选中目标”简单等同“已死亡”，须考虑中毒、有效保护、市长等）；③**只有非唯一规则分支**才向 AI/人工请求裁量，例如市长转移、登记歧义、醉毒错误信息和首夜策略选项。健康占卜师查两人，在考虑真实恶魔、红鲱鱼、Spy/Recluse 登记后若答案唯一，则 Host 直接显示；死亡发生于后续行动之前时不再唤醒死者。实际曾错误展示的信息必须可经**独立的显式纠错/实际事件**如实记录，但不能把常规唯一结果设计成供说书人随意选择的菜单。

跨 Android CampHost、独立 WebHost 与 EvidenceLab 统一的是**状态/事件语义合同**，不是 Android UI、进程或新建一个双轨恢复系统。最低限度中断续局可复用相同事实，避免完整 UI 复原/重复文字记录/独立存档。

## 已有 AI 与可能将来从零重建的 Rules

Rules：规则**执行**属于 Host Core，不新增第三套状态或大型旧 Rules 引擎；仅删除冗余候选合法域、通用推演、重复判定及影子控制。窄范围已实现的确定结算如果正确，应优先保留/简化；此前删除而尚未等价替换的确定能力必须标为待恢复。可选的将来独立只读 Rules 顾问不是现阶段前提。

AI Clues：**现有首夜整局规划、后夜增量规划、API/提示词、解析、战略记忆、辅助/自动模式全部保留**。AI 对多种真正许可的结果做策略裁量；结果唯一时不得为征求判断而发起 AI 请求。Host 的确定性规则事件和实际已展示的信息都由唯一 Session 留痕，必须区分正常规则输出与显式纠错；不能把 AI 意见当作事实。
