# 最小 Host 事实合同（2026-10-18 修订）

当前产品有**三个职责模块**，不是永远取消规则检查：先建设通用的 Host Core，旧 Rules 全部退出后**从零**重建 Rules；旧 AI 线索模块退役后再重新设计 AI Clues。详细路径：docs/HOST_RULES_AI_REBUILD_AND_SOURCE_PURGE_2026-10-18.md。

## Host Core

拥有一局游戏唯一可写状态与顺序事件：对局/座位、真实与展示身份、角色状态、生死、阶段、初始配置、选定酒鬼、玩家行动、说书人真实决定和实际告知玩家的信息、提名投票/处决、状态变更、阶段推进。事件只记录最终确认发生了什么，不区分 AI 采纳还是人工覆盖；不能凭显示结果推断未明确选择的登记事实。

Host 只验证数据形状、角色/座位是否存在、对局身份、序列时间顺序、重复事件、原子提交、私密可见范围、过期 AI 请求/安全。Host **不验证规则合法性、不计算结果、不以 Rules/AI 推荐作为事实提交前置条件**。允许说书人手动指定任何结构可表达的信息并如实展示/记录。

跨 Android CampHost、独立 WebHost 与 EvidenceLab 统一的是**状态/事件语义合同**，不是 Android UI、进程或新建一个双轨恢复系统。最低限度中断续局可复用相同事实，避免完整 UI 复原/重复文字记录/独立存档。

## 将来独立 Rules 与 AI

Rules：只读 Host 状态、指定角色、时刻、查询目标，返回合法候选帮助用户选择。不得写事实或阻止手动输入。所有**现有**规则、合法候选生成、Spy/Recluse 见证、Host 自动真值裁定及相关专属测试现阶段都要删除，不迁移算法。以后新 Rules 提供 pair 目标/角色动态选择、厨师上下限、共情者即时合法按钮等体验。

AI Clues：只读 Host 状态和实际事件，推荐专家级线索；只有真正被确认的信息可通过 Host 提交。旧候选 ID/评分/世界推演协议退出，新接口等 Host 稳定后规划。维护必要密钥、传输、会话安全但不要复制事实/历史。

## 整体交付要求

执行 P1 删旧规则 → P2 删旧 AI/推演 → P3 收敛 Host → P4 净删 UI/所有源码 <=50,000 bytes → P5 全仓复核、跨项目合同与新 Rules/AI 规划。清理期间允许旧 Rules/自动 AI 不可用，但须保留核心手动游戏操作、可信事件、隐私、提交一致性。旧行为回归测试可随过时产品退休，核心事件、安全测试继续执行 GitHub CI/R2。
