# 最小 Host：当前产品边界

状态：项目所有者于 2026-10-17 明确改变目标；本文件与 CURRENT_DEVELOPMENT_ROADMAP 为当前权威。实现尚未完成，不把新方向描述为现有功能。

## 目的

Host 只维护继续游戏所需的当前状态、一份权威游戏记录和必要操作。AI 负责分析与推荐，说书人负责游戏规则正确性。Host 不再保证线索或操作符合游戏规则。

最小验收例：AI 建议“3 号共情者收到 1”，说书人确认后，同一次操作记录并展示“1”。Host 不计算正确数字、不枚举合法答案、不反推登记解释。AI 未采纳建议不是事实。

## 保留

- 玩家、稳定座位与身份、存活状态、阶段/轮次和实际继续游戏所需的已确认状态；具体最小字段在删除审计中逐项确认，不继承旧 Session 全部字段。
- 一份按实际顺序记录的初始配置、玩家行动、说书人决定、提名/投票和实际公布信息。AI 输入、文字展示和未来中断续局共用这份记录，不建立独立事实副本。
- 基本人工操作：录入结果、死亡和身份变化、提名投票、推进阶段、私密身份/信息展示。删除方桌线索辅助不等于删除必要操作入口。
- 数据完整性：对象/座位存在、当前对局身份、状态与记录一致提交、重复提交防护、过期 AI 响应隔离、隐私及凭据安全。
- AI 请求/响应的必要结构检查和当前请求关联；这不包含游戏规则合法性检查。

## 删除目标

- Host 的游戏规则合法性校验、线索计算、合法候选枚举和策略排序。
- 为解释一个结果而反推的间谍/隐士登记证据，以及只服务于该验证链的快照、适配器、候选和中间状态。
- 全手动界面的规则/线索辅助、自动正确答案与相关预览。
- 仅保护以上已取消功能的测试及源码形状守卫，与生产依赖一起退休。

明确由说书人输入的登记裁定可以作为决定记录；不能仅因某结果存在一种解释就补写未发生的裁定。哪些旧记录结构仍有必要，应从真实消费方重新决定。

## 不做

不复活独立存档、精确 UI 恢复、全量技术事件溯源或旧格式兼容。不让 AI 未确认响应直接覆盖游戏事实。不为取代旧规则引擎新建复杂的通用 AI 自动执行框架。自动模式的保留范围、执行授权及交互需在新审计中明确，不默认沿用旧“合法候选自动确认”机制。

## 执行顺序

1. 从最小人工/AI建议确认流程列出保留入口、状态和事件，审计全部读写者及两个脚本的消费链。
2. 标出整条可删除的规则、候选、辅助展示、provider legal-menu 和测试依赖；AI 请求协议也要同步审计，不能只删除 UI 校验。
3. 分批删除并切换到简单的结果录入与记录边界。允许明确缺口，不先搭建庞大替代体系。
4. 对剩余代码重新量化与拆分；不继续旧 D5 的规则模块提取计划。
5. 后续单独完善必要事件覆盖和可靠本地持久化，实现同一局意外退出后的最小继续游戏。

原子性、发布真实性、隐私和过期响应的测试继续保留。规则测试按取消的产品合同退休，不要求新实现通过被明确取消的规则行为。真实模型付费调用仍需单独预算授权。无真机或付费模型验收不能表述为已完成。

## 2026-10-18 优先级修订：全仓减法与源码上限

以逐模块全树遍历审计替代局部 UI 功能补丁；只保留当前状态、一份权威关键事件记录及必要操作。每个源代码文件不得超过 50,000 字节，先删未使用功能，再拆分仍必需的责任。人工信息界面在清理期不设置任何游戏规则合法候选限制，数据结构/隐私/时序防护仍保留。座位对相关角色候选、厨师数值边界、共情者动态合法按钮全部推迟到**完成清理之后的第二阶段**，不得为此保留或重建旧规则引擎。完整库存与待审核见全仓审计台账。
