# Host → Rules → AI 重建与全仓清理路线（权威）

**批准日期：2026-10-18。状态：后续实施的唯一专项产品和开发路线。** 旧 M1a–M1d、D5、旧 Host 规则保留及旧推荐候选优化路线已停止驱动开发，历史提交不等于此路线已完成。

## 一、最终三模块及边界

### 模块 1 Host Core — 先实现、唯一事实来源

- 唯一状态：对局、剧本、玩家与座位、真实和展示角色、存活、阶段/轮次、实际选定目标和必要状态。
- 唯一按发生顺序记录的关键结构化事件：初始配置、酒鬼确定、行动与说书人实际决定、给玩家实际公布的信息、提名/投票/死亡/处决、身份/状态变化、阶段推进等。
- 唯一提交权：真实行动和展示信息只有确认后才能成为事实，无论建议来源 AI 还是人工。不要第二条 AI 采纳/覆盖事实，也不能因为显示某结果就反推没有实际选择的 Spy/Recluse 登记。
- Host 只检查结构、座位/游戏身份、时间线、重复提交、原子提交、权限/私密可见范围、过期 AI 响应与安全；**不计算游戏合法答案，也不依赖 Rules 来允许提交事实**。
- Android Host、独立 WebHost、EvidenceLab 应共用同一状态和事件语义合同；不等于要求三个仓库共用语言、进程或现在建一个大框架。UI/最小持久化/安全通信是薄适配层而不是第四套事实权威。

### 模块 2 Rules — 现有实现完全退休，后续从零重建

- 以后读取只读 Host 快照、角色、查询目标及当前状态，返回合法信息候选给操作界面。
- 不拥有状态、事件或提交权；无论 Rules 的建议如何，都不能阻止说书人实际确认并记录某条信息。
- **此次清理整链删除现有规则检查实现**：legal domain、固定规则数值、注册见证、历史世界验证、自动结果选择、与这些相关的调用及旧测试，不保留兼容壳、不迁移旧算法，也不为了旧规则测试复活功能。
- 清理完之后才规划 Rules 新合同和便利操作：pair 先选两座位再提供相关角色选项；厨师开局依据清醒/醉毒状态准备可能的数字范围；共情者每次按自己及活着的邻座现状提供合法按钮。当前阶段一概不实施。

### 模块 3 AI Clues — Host 清理后重新规划

- 读取 Host 唯一状态、已确认事件和必要上下文，给出一条或多条接近专家说书人的线索建议。采用建议统一由 Host 确认入库。
- 退出旧 Host 合法候选 ID、评分、预测假设世界、A4/B4/ZDD 与旧上下文投影协议。保留实际必要的密钥保护、通信与过期请求隔离；现有 AI 推荐短期可以停用。
- 后续模型选择、训练、提示词、长期策略记忆等只有在 Host 数据合同稳定后再设计。真实收费模型调用仍需另行授权预算。

## 二、如何遍历、判断、删除

对**整个仓库全部代码文件**逐一审计，不沿旧架构现有函数路径增量补丁；对每个文件标记：
1. 唯一事实、事件、必要操作或安全 —— 保留最小责任并剥离旧规则/推荐；
2. 旧 Rules/AI/影子推演/历史实验或不属于三模块且不承担必要基础设施 —— **直接删**；
3. 混合职责 —— 先删除过时消费者、结果计算与旧测试，再保留核心事实提交职责；
4. 不确定 —— 提交给所有者审核简短证据（功能、生产使用、可能损失、推荐），允许认真考虑先删除、未来在正确边界补回，禁止建立长期双轨兼容。

**删除目标即使有生产调用者，也不自动保留；应先切断不需要的调用再删全链。** 删除专属旧测试、过时 R2 源码形状守卫、过时文档；保护高价值状态/安全证据。不要创建代理函数或 God Context 来保住旧算法。

人工展示信息清理阶段**完全不受游戏规则候选限制**；仍须记录接收玩家、当前轮次、信息类型、目标及真实展示内容，并保护私密性/数据结构。

**硬性规模目标：所有代码类源文件 <= 50,000 字节**（十进制，不只 Android Kotlin）；先真实净删除冗余，再为仍需要的职责拆文件，不是为过线而机械分块。

## 三、实施阶段与验收

### P1 删除旧 Rules（下一轮直接实施）

盘点 clocktower/rules 下所有旧文件及其跨 App/HostScreen/NightStepUi、Session、Setup、Flow、Recommendation、Provider、测试/CI 的真实生产调用。先切断 Host/UI/AI 对合法候选、自动真值、Spy/Recluse 登记推断的依赖，保证人仍可选、展示、确认实际结果；整体删除旧规则算法、专属 DTO/测试。不要为临时恢复自动模式而保留规则逻辑。

**P1 验收：**基础 MANUAL 模式可以开局、显示魔典/私密信息、记录实际行动、死亡/投票、推进阶段，事件可信；旧 Rules 生产消费者清零或列出具体阻碍。相关构建与 CI/R2 通过；可明确报告暂时缺失的规则自动裁定/AI 功能。

### P2 删除旧 AI 候选与历史世界推演

按消费者整链退役旧推荐评分、候选 ID 合同、Setup 候选策略、A4/B4/ZDD/世界枚举、Topology 历史推演、影子缓存和对应测试/工具。实际事件时间线及玩家收到信息的记录仍属于 Host，**不得误删**。

**P2 验收：**Host 不依赖旧 AI/世界推演仍可独立操作；保留最小传输/凭据/过期处理；旧影子推演与候选身份不再是生产合同。

### P3 唯一 Host 状态及事件合同收敛

核对 GameState、GameSnapshot、ClocktowerSessionState、PlayerCard 等生产存储与派生对象；唯一可写事实和唯一关键事件序列，最小读接口和提交事务。完善必要的实际事件覆盖及中断后的最小安全继续，不重建独立 Recovery、重复文字复盘或第二份事实副本。

**P3 验收：**事实、身份、顺序、去重、隐私一致，能够从已确认事实继续；纯数据合同不依赖 Compose 或 Android 专有类型。

### P4 UI 剩余职责/源码大小治理

Android App、HostScreen、NightStepUi 留必要导航、魔典/方桌、人工选择、确认发布、阶段推进与设置，其余整段净删。对于仍超 50,000 字节的源码，再按真实职责拆分，禁止透传壳、重复状态与巨型参数对象。

基线超限：CampBoardGameHostApp.kt 198,706 B；ClocktowerHostScreen.kt 150,032 B；ClocktowerNightStepUi.kt 60,272 B；web/app.js 143,503 B。旧 web/ 是独立离线网页产品，仍有 Undercover、狼人杀和独立 localStorage；是否将其整包退休仍需用户审核，不自动当作独立 WebHost 的统一核心。

**P4 验收：**每个源码文件 <= 50,000 字节，且组件责任真实解耦。

### P5 完整复查，才开始规划新版 Rules / AI

再次对全部代码源文件逐项核对保留责任、生产消费者及大小；给出净删除数量、超限归零证据、唯一状态/事件的调用关系、剩余缺口和最新 CI/R2。然后审计 CampHost、独立 WebHost 和 EvidenceLab 的状态事件合同共享，最后规划并实施新的 Rules 与 AI。

## 四、执行和证据原则

- 先核对 GitHub/main/PR HEAD/base、CI/R2、开发机 Git branch/HEAD/clean；远端真相以 GitHub Connector 为准，Mini MCP 用于必要完整文件/本地编辑。不可假设本地等于远端。
- 每批以净删为导向：先查消费者和事实保护范围，删除旧生产+专属测试，运行足够独立的现存测试和 GitHub CI/R2，失败直接读日志修复。
- evidence-first 而不是机械 test-first。**旧 Rules/AI/影子算法测试不再是产品要求**；不要为了旧测试绿色而留下旧实现。保留单一状态、事件顺序/一致性、去重、私密信息、过期响应和必要操作的验证。
- 每批报告旧模块关闭的实际引用、删掉的文件/行/字节、仍超限文件和真实 CI/R2。每轮只更新 CURRENT_DEVELOPMENT_ROADMAP、NEXT_DEVELOPMENT_HANDOFF 和必要审计数据，禁止叠加新的过时 NEXT。
- PR 保持 Draft；用户没有授权本轮自动合并这些堆叠 PR。无强推，无擅自删除远端分支，付费 API 和真机测试另行授权/安排。
