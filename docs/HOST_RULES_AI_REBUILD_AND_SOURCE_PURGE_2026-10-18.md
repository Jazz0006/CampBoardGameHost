### 1. Host Core：唯一事实和安全提交权

- 唯一真实 GameState/Session 与按顺序记录的结构化关键事件：座位、真实/展示身份、酒鬼选择、状态、夜间行动、信息公布、投票、死亡、阶段变更等。
- 除结构、座位/身份、权限隐私、提交、去重、时间线和过期检查，还应**即时计算并执行规则确定的结果**：Imp 袭击须先考虑真实角色/中毒/僧侣/士兵/市长等；确定死亡立即改变夜间存活与其后唤醒；占卜师在考虑真正恶魔、红鲱鱼及隐士/间谍可选登记后如仅一项结果就由 Host 自动揭示。允许明确纠错来如实记录现实中已经展示的错误信息，不把纠错误当通常裁量。
- **规则唯一结果不能常规交 AI/人工自由选择**；Host 校验机器自动步骤符合确定性游戏规则，但不得掩盖已经发生的误操作，应通过显式纠错/实际展示记录路径留痕。Spy/Recluse 登记选择如果影响信息，必须有明确裁量事实；不得由公布值反推未确认登记。
- Android CampHost、独立 WebHost、EvidenceLab 以后共享的首先是状态/事件语义合同，而不是立刻迁移语言或复制另一份写入状态。

### 2. Rules：保留最小确定性执行，退休旧通用合法域／重复引擎

- **不要为了旧架构而保留旧引擎，但也不要为了全删目标砍掉必要规则。** Host 可以复用经过验证的简短确定规则函数，且应补足其测试。未来可选只读 Rules 服务不负责替代 Host 必需的固定规则执行。
- **P1 待删除**：大规模候选枚举、重复真值计算、多世界枚举/专用见证对象、shadow control 与多层适配。**P1 不得删除**：只有一个规则结果时的 Host 自动推导、真实保护/死亡与角色唤醒、真实唯一信息和必要事件测试。对旧删除批次做 forced/discretionary/duplicate 逐项复核。
- **AI 不需要 Host 预先枚举全量候选**，但非唯一决策必须遵守对应规则许可的选择范围；确定性结果由 Host 本地执行，不发送模型。保留真实 AI 请求、结构化响应、战略记忆、安全、时序与私密发布。不得重新引入旧大规模合法域，也不得容忍“唯一结果也由 AI 任意编造”。
- 未来操作便利：pair 选两座位并给相关角色选项、厨师可能数字、共情者对应阶段的数字按钮等。不可把这些按钮变成 Host 拒绝实际信息的硬检查。

### 3. AI 推荐：保留现有已经研发、测试的产品功能

- **完整保留并继续维护：** 首夜整局联合规划、逐步信息预选、AI_ASSISTED 和 AI_AUTOMATIC、真实 OpenAI API 接入与认证、生产提示词、响应解析、会话与请求合同、全局战略记忆、连续夜晚增量规划、战略去重、安全响应隔离。
- AI 从真实局面和事件理解战略，但**只能裁量规则真正留下的非唯一分支**，不需要 Host 全域枚举候选。Host 在唯一结果时直接提交真实计算结论，并对 AI discretionary 返回执行轻量、可解释的本角色规则限制（不是恢复旧泛化候选引擎）；结构/身份/版本/隐私/确认仍要检查。实际误操作可通过独立更正事件如实保留。
- 可清除与生产 AI 无关的废弃实验、重复评分或 shadow/world 推演，但必须先证明确无有效生产 AI 消费者；**P2 不再是“删除旧 AI 系统”。**
- 模型品质/性能优化与新版 Rules 的单向咨询接口后续逐项推进，不因当前 Host 清理而主动退役已有可工作的 AI 推荐。真实付费调用需要另行授权。

## 2026-10-19 补充：以产品必要性而非生产调用判断删除

**现已修正的正式标准：不仅能否继续点击，还必须保持规则正确。** 检查当前游戏是否会因为移除该功能而无法**正确**继续：必要的规则确定计算不能通过“说书人可以手工补”视为可删。如果还能由说书人手动完成、共享方桌直接呈现或现有 Host/AI 路径代替，应删除整条旧生产调用链及独占测试；即使目前有调用，也不得仅因此认定必须保留。保留不能替代的唯一 Session/GameState、完整结构化事件、实际公布信息、基础游戏步骤、AI 规划/传输/战略记忆和必要安全/隐私/原子性。避免针对小概率特例专门重新工程化。一个功能被产品删除后，相应测试/序列化/令牌/依赖图/适配器不应因为互相调用而长期存留。

**已明确的 Spy 例子**：首夜/后夜只保留常规间谍唤醒步骤，当前说书人方桌直接交给间谍看，收回手机后点击原下一步。取消单独玩家魔典展示页及展示按钮；不再构建专用 GrimoireState/Reminder Token/魔典快照，也不让 Spy 的查看成为红鲱鱼设置的额外依赖。中毒间谍由说书人自行处理，当前不另建特别流程。此项不删除真实当前方桌、间谍实际角色/登记操作、其他玩家私密信息及 AI 历史。

**2026-10-19 再次纠正清理边界（优先级高于上文通用减法原则）**：明确保留开局避免连续重复的**阵容多样性**，也保留同一玩家跨局尽量不拿重复身份/角色的**个人身份轮换**。这是现行产品体验，不是Host的游戏规则真值审查，也不能拿“手工仍能开一局”为由删除。SetupDiversitySelector/History、TB预设生成选择、历史记录Store/Record、角色分配旋转规划与相关测试都保留；只在验证真正等效且得到明确批准后才可能改写。前一批尚未提交的删除已从开发机完整恢复，工作树复核无遗留。其它旧合法候选门禁、shadow public replay、自动单例判定等仍按产品必要性删除。

## 三、删除边界和验收

每个候选删除都分类：Host 必要事实与操作、Host 规则门禁、AI 生产推荐依赖、纯死代码/实验。对于混合文件，仅去掉 Host 合法性否决；不能把“AI 也用到了规则候选”错误视为删除整个 AI 消费者的许可。没有生产消费者的旧试验可以直接清理并删专属测试；有 AI 消费者的先保留功能再重构。

最小 Host：开局、角色展示、说书人当前方桌/魔典（日间及夜间直接查看，非独立Spy页）、日夜步骤、投票死亡、私密公布、手动信息录入与唯一事件写入。AI：首夜计划、配对与数字等推荐、后续夜晚推荐、辅助/自动模式的结果展示与采纳、真实 API/策略记忆流程不允许无意回退。端到端真机和付费 API 没执行就不得声称通过。

测试采用 evidence-first；针对 AI 合同和安全、**确定死亡/保护/唤醒/信息计算、真正可选登记和毒醉例外**保留/补建行为测试；只属于旧通用候选门禁或废弃实现形状的测试可删。每次代码提交通过当前实际 GitHub CI/R2，必要时用 [full-ci]；报告净删除/恢复量、真实消费引用和超限文件。绝不以历史文档代替实际 HEAD 证据。
