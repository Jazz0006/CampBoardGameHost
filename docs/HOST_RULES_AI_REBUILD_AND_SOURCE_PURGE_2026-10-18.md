# Host 规则检查清理与 AI 推荐保护路线（权威，2026-10-18 修订）

**所有者纠偏：此次清理是针对 Host 中过度工程的规则合法性检查，不是删除现有 AI 说书人推荐系统。** 本修订覆盖同日早期“删除旧 AI、以后从零重建”的表述。已发生的 B1–B3 提交和 CI 结果仍是历史事实；B3 误删的 AI 配对推荐链必须先恢复再继续清理。

## 一、三模块的最终职责

### 1. Host Core：唯一事实和安全提交权

- 唯一真实 GameState/Session 与按顺序记录的结构化关键事件：座位、真实/展示身份、酒鬼选择、状态、夜间行动、信息公布、投票、死亡、阶段变更等。
- 只校验数据结构、座位/身份引用、权限隐私、原子提交、去重、时间线和响应过期。人工、AI 辅助或自动模式最终确认的结果统一作为实际事件；不记录额外的“AI 采纳”或“人工覆盖”事实。
- **不得验证信息是否符合游戏规则，不得因 Rules 或 AI 的规则意见拒绝记录已经实际给出的信息。** 不从一条公布信息反推 Spy/Recluse 登记或其他未确认事件。
- Android CampHost、独立 WebHost、EvidenceLab 以后共享的首先是状态/事件语义合同，而不是立刻迁移语言或复制另一份写入状态。

### 2. Rules：独立、只读的合法信息查询服务

- 未来读取 Host 当前状态、角色、时刻和目标，提供合法信息与操作便利选项，不写 Host 状态，不参与事实提交许可。
- **P1 要删除的是 Host 内的旧合法性门禁、重复真值计算、见证推导、旧规则拒绝人工结果及专属过度工程。** 不用把已有 AI 整局规划一起删除。
- **再次确认：AI 不依赖 Host 提供候选。** 当前仍被生产代码消费的 Host 旧候选生成、合法域匹配和响应规则拒绝仅是待拆的技术耦合，标记 REMOVE_AFTER_DISCONNECT。先保留真实 AI 请求与结构化响应、战略记忆/预选、安全/时序/身份检查，再删除旧合法候选计算与 Host 规则否决；不必等未来 Rules 重建。不得让真实 AI 推荐中断，也不得新增另一套规则判定壳。
- 未来操作便利：pair 选两座位并给相关角色选项、厨师可能数字、共情者对应阶段的数字按钮等。不可把这些按钮变成 Host 拒绝实际信息的硬检查。

### 3. AI 推荐：保留现有已经研发、测试的产品功能

- **完整保留并继续维护：** 首夜整局联合规划、逐步信息预选、AI_ASSISTED 和 AI_AUTOMATIC、真实 OpenAI API 接入与认证、生产提示词、响应解析、会话与请求合同、全局战略记忆、连续夜晚增量规划、战略去重、安全响应隔离。
- AI 根据 Host 真实局面、已确认事件和自身剧本知识直接全局规划给谁什么信息，**不接收 Host 给出的合法候选**。Host 仅凭结构、身份、版本、隐私及确认边界提交实际事实，不通过旧 Host 候选域重新判定信息真值。
- 可清除与生产 AI 无关的废弃实验、重复评分或 shadow/world 推演，但必须先证明确无有效生产 AI 消费者；**P2 不再是“删除旧 AI 系统”。**
- 模型品质/性能优化与新版 Rules 的单向咨询接口后续逐项推进，不因当前 Host 清理而主动退役已有可工作的 AI 推荐。真实付费调用需要另行授权。

## 2026-10-19 补充：以产品必要性而非生产调用判断删除

**正式标准**：检查当前游戏是否会因为移除该功能而无法继续。如果还能由说书人手动完成、共享方桌直接呈现或现有 Host/AI 路径代替，应删除整条旧生产调用链及独占测试；即使目前有调用，也不得仅因此认定必须保留。保留不能替代的唯一 Session/GameState、完整结构化事件、实际公布信息、基础游戏步骤、AI 规划/传输/战略记忆和必要安全/隐私/原子性。避免针对小概率特例专门重新工程化。一个功能被产品删除后，相应测试/序列化/令牌/依赖图/适配器不应因为互相调用而长期存留。

**已明确的 Spy 例子**：首夜/后夜只保留常规间谍唤醒步骤，当前说书人方桌直接交给间谍看，收回手机后点击原下一步。取消单独玩家魔典展示页及展示按钮；不再构建专用 GrimoireState/Reminder Token/魔典快照，也不让 Spy 的查看成为红鲱鱼设置的额外依赖。中毒间谍由说书人自行处理，当前不另建特别流程。此项不删除真实当前方桌、间谍实际角色/登记操作、其他玩家私密信息及 AI 历史。

## 三、删除边界和验收

每个候选删除都分类：Host 必要事实与操作、Host 规则门禁、AI 生产推荐依赖、纯死代码/实验。对于混合文件，仅去掉 Host 合法性否决；不能把“AI 也用到了规则候选”错误视为删除整个 AI 消费者的许可。没有生产消费者的旧试验可以直接清理并删专属测试；有 AI 消费者的先保留功能再重构。

最小 Host：开局、角色展示、说书人当前方桌/魔典（日间及夜间直接查看，非独立Spy页）、日夜步骤、投票死亡、私密公布、手动信息录入与唯一事件写入。AI：首夜计划、配对与数字等推荐、后续夜晚推荐、辅助/自动模式的结果展示与采纳、真实 API/策略记忆流程不允许无意回退。端到端真机和付费 API 没执行就不得声称通过。

测试采用 evidence-first；针对重要 AI 输入输出合同、提示词/语义路由、战略上下文、模型传输/过期保护及 Host 真正事件提交留测试；纯旧 Host 规则合法真值的测试可删除。每次代码提交通过当前实际 GitHub CI/R2，必要时用 [full-ci]；报告净删除/恢复量、真实消费引用和超限文件。绝不以历史文档代替实际 HEAD 证据。

维持现有 #330–#334 堆叠 Draft，不自动合并、强推、清理远端分支。付费 API 调用须独立预算授权。
