# AI-STORYTELLER-CONTINUITY-1 — 连续对话、游戏记录驱动的按需裁量与长期战略记忆

> 产品设计更新：2026-10-15（Australia/Sydney）。**最新批准的产品决策：开局联合全局规划，后续必要时仅请求当前一项线索。后续的“整包 remainingChoices”方案被替代，不得继续作为强制开发合同。** 当前仍需实施与验证；本文件不是生产实现验收。
> 当前任务入口：[roadmap](CURRENT_DEVELOPMENT_ROADMAP.md) / [handoff](NEXT_DEVELOPMENT_HANDOFF.md)。旧 3E/3E2/3E3 文档是各阶段的实现证据，不能覆盖本文件的新产品目标。

## 1. 单一专家说书人的产品目标

- **每局游戏只有一条持续演进的 AI 战略对话**：开局联合考虑真实与展示阵容、玩家经验、善良信息生态、邪恶压力与可维持的伪装、多夜可能发展；AI_ASSISTED 与 AI_AUTOMATIC 使用同一个策略控制器。
- **确定人员配置及展示阵容后立即发起一次初始全局请求**，与逐个展示身份的操作并行。联合考虑 Drunk（如有）、红鲱鱼、恶魔掩饰身份、当时可合法确定的首夜线索与多夜战略；保留可用的预推荐缓存。未来玩家行动尚未发生时可保留条件性意图，不得虚构实际信息；不要求所有延期信息在首轮都已有确定值。**绝不先单独请求酒鬼，再补一轮全局分析**。
- 已考虑但没有输出的模型推理可能有战略价值；尽可能验证 Responses 连续对话及兼容模型的跨轮推理复用，但它**不是 Host 事实、不是可阅读的完整思考存档，也不是无需验证的稳定长期记忆**。
- Host 持有唯一规则与 Game State 权威；产生合法当前候选、确认事件与历史、判断何时可裁量及何时公布。**首次是整局联合规划；后续每次真实需要模型时只返回当前正在请求的一项 Host 合法线索**，但必须以全局战略、已有线索和新增事件为依据，绝不是旧式逐角色孤立推荐或评分器。不能生成未发生的行动、唯一注册见证、预设未来玩家选择或修改已公布结果。
- 追求两边公平、可推理且多种世界并存；照顾新手邪恶玩家实际能持续扮演的伪装，同时保留善良方可理解的检验线索。不以某一方必胜为目标，也不把盲测例子做成规则特例。
- 不随每次开夜单独重新从头规划，不引入各角色或各事件专属 AI 调度，也不复活旧加权、逐项排序器或 V1 单点推荐。

## 2. 三层记忆与唯一真相

| 层 | 权威与生命周期 | 用途 |
| --- | --- | --- |
| **Host 局内事实账本** | 唯一权威，事件溯源/单调序号；保存实际角色/展示身份/状态/规则登记裁定、玩家已收到的线索、提名/投票/处决、人工修改和有来源的声称；可恢复 | 从模型建议中区分**已执行、未采用、尚未公布、撤回/纠正**；不把猜测升级为事实 |
| **同局 AI 对话与战略假设** | 由已确认的对话锚点延续，依赖 Host 输入与 provider 可用性；允许修订/淘汰旧意图 | 记住开局信息锁定风险、可疑登记的不同世界、善恶压力、预备伪装、多夜线索意图及变化缘由 |
| **跨局战略经验库** | Host 本地长期存储；以完成/已实际执行的对局记录为准 | 对新局提供相关的结构化过去配置与套路摘要，避免熟悉玩家反复遇到近似体验；不把旧局对话拼接为新局身份或事实 |

目标路径：首轮输入完整局面；后续只有确实需要新的当前线索时，发送**自最后一次已确认的 AI 对话锚点/因果游标以来所有新增游戏记录 + 当前阶段、轮次、版本 + 当前这一项 Host 合法候选**。被拒的模型结果不能成为新锚点，因此必须从上一个可确认锚点补齐事件，不能只机械地从最近一次网络请求算起。API 续接期间每轮重送核心指令和严格 JSON 合同；锚点丢失/拒绝时改用完整 Host 事实快照和简短战略恢复。已实现 P1 的第一阶段仍重发完整 Host 状态，**增量仅是下一阶段目标**。Host **永久掌握事实**，不把服务端对话当作唯一存档。

## 3. 连续 Responses 协议（待实现与真 API 证实）

- 为每个 gameId 建立一条逻辑上的 Responses 续接链；保存**最后 Host 确认可延续节点**的 response_id、模型家族、协议版本、Host 事件序号/各 revision、已接受/公布的决策标记。
- 已有 P1 首版的 `store:true` + `previous_response_id` 续接实现（原 #308 已纳入统一 Draft #315，旧 PR 关闭未合并；CI/R2 已通过，待真机）。下一阶段目标：只传输游标之后的因果增量与**当前单项合法裁量**；Conversations API 或 `store:false` 加完整/加密历史重放仍可作为失效备选，不把未测试的方案称作生产能力。
- 遵守 provider 当前的数据保留、对话与模型支持限制。长于两小时的游戏不应因“时长”自动切断；受限于 response 保留/失效、context token 与费用，而非局内游戏时间。当前 ≤4 小时意外关闭恢复范围仍按既有产品决策，不在本路线扩展。
- 需要**实测**当前 `gpt-6-luna` 是否支持 `reasoning.context = all_turns`、返回的 effective 模式和跨轮行为。官方文档列出某些支持的模型家族不等于我们部署的具体模型必然支持。若不支持或无明显收益，则依赖显式短战略记忆，**不可冒充已保存模型内部推理**。
- 内部推理不作为可读取的长篇 chain-of-thought；不向用户/日志承诺显示其原文。保留可检查的简短战略锚点（主要张力、条件意图、待确认事实、明确的修订依据）是独立保险。
- 记录逐请求的实际 `input_tokens` / cached input / `output_tokens` / reasoning tokens（如 API 可得）、耗时、请求失败和剩余 context；历史上下文**仍可能在后续请求计费**，增量传输并不等于零成本。优先衡量质量，再根据实测选择压缩/摘要，禁止无证据声称 5 秒内重规划。
- **上下文分叉安全**：过期响应、未采纳方案、并行回应不得推进唯一 canonical conversation head。手动覆盖需明确区分原提案和实际采用；必要时从最后已确认锚点 fork，并注入 Host 最新事件。失败后支持事实账本 + 精简战略锚点的恢复，恢复时丢失隐性推理要如实标记。

官方参考（实现前复查最新）：https://developers.openai.com/api/docs/guides/conversation-state ；https://developers.openai.com/api/docs/guides/reasoning 。

## 4. 通用事件 → 推荐有效性 → 当前单项裁量（2026-10-15 新批准路线）

```text
确定座位及展示身份阵容（逐人亮牌之前）
    -> 后台发起一次初始全局战略与合法开局配置联合规划
    -> 首轮可预定的线索写入“未发布建议缓存”（不是 Game State）
每一个真实 Host 决定、人工覆盖、行动、公布信息或玩家声明
    -> 写入魔典/局内不可变事件账本（来源、序号、轮次、真实状态）
    -> 同时维护“模型提议”与“实际采纳”的不同来源
下一项确实需要信息/选择的时刻
    -> Host 计算当前合法玩家可见结果 + 观察当前事实
    -> 唯一玩家可见合法结果：Host 直接确定；不请求 AI
    -> 已有缓存推荐且仍合法、依赖前提有效、战略没有受实质影响：
           复用推荐；不请求 AI
    -> 没有推荐，或相关事实/人工覆盖令推荐失效：
           从已确认对话锚点取得缺失的全部有序事件
           + 当前事实版本/阶段/轮次 + 这一项语义需求（合法域由 Host 内部保留）
           -> 续接同局全局战略，只输出“当前这一项”数字/真假/角色/配对等直接语义结果
           -> Host 校验合法性、事件游标、revision、来源及返回语义
           -> 辅助确认或自动安全私有预选
           -> 真正提交/公布时才写入 Game State 和玩家已知事实
    -> 进入下一个需要决定的时刻
```

- **推荐缓存有效性不是“上一条是否采纳”的简单布尔值**。人工否决/覆盖使相关建议进入待复核状态；新的行动、状态、已公布信息也可能令建议失效，即使上一条已采纳。若 Host 能明确证明缓存的依赖没有被改变，可保留；否则废弃并按需重新裁量。不能因无关事件机械清空全部缓存，也不能仅凭表面候选仍合法便认定战略未变化。
- **魔典是唯一事实权威**：最终 Drunk/红鲱鱼、各角色实际观察、投毒/处决/声明等无论是否来自 AI 推荐都必须记录；未采用的 AI 选择记录为“提议/被拒”，不能覆盖真实决定。玩家已经收到的结果不可撤回。初始酒鬼只有在真正 Host 确认后才成为事实。
- **模型只给当前一个结果，绝不意味着只看当前角色**。模型直接输出一个语义结果，不接收 Host 枚举 candidateId；共情者返回 `0/1/2`，中毒的占卜师返回 `有/没有`，送葬者在多个合法选项中为一个角色名，成对信息直接表达两个座位与角色、由 Host 后验验证并展示。模型持续参考全局身份/信息交叉、邪恶新手压力、红鲱鱼、醉酒因果、跨夜策略。避免自由文本结果及未经证实的 Spy/Recluse 唯一登记。
- **按需请求与后台预取并存**：下一项确实会需要新的模型裁量且依赖的玩家行动已确认时，可在上一项信息展示期间预取；预取绑定精确 Host revision/因果游标，事实变化即淘汰，绝不可预言玩家尚未选择的行动。已经有有效推荐不再产生付费请求。
- **不以“每事件一调用”实现事件驱动**。事件总是先登记；真正需要当前且结果有多种可区分语义时才触发 AI。多个短时事件应聚合到下一次必要裁量的请求里。无网/超时/非法/歧义时安全转人工，禁止回退旧的无状态逐点 AI 推荐器。

## 5. 玩家身份声明和邪恶掩饰意向

- 在座位头像**长按**进入轻量选择器：先选记录类型，再选角色。
- `PUBLIC_CLAIM`：玩家在公开场合声称某角色；记录 sourceSeat、claimedRoleId、阶段/轮次、Host 记录时间/序号、公开范围（若未知显式 UNKNOWN）。**公开声称不等于真实身份**。
- `PRIVATE_BLUFF_INTENT`：玩家私下告知说书人希望扮演的身份；标记为意向，不能自动视为已经对全场公布。不要将其传成所有玩家都知道的事实。
- `CLAIM_CHANGED` / `CLAIM_RETRACTED`：变更/撤回追加新事件，不覆盖原历史；允许多项并存、互相矛盾、信息来源不完整。
- Host 将这些标记加入经过来源标注的事实账本；它们影响信息生态与掩饰可维持性，但只是玩家言论/意图，**不自动触发模型调用**。不能编造玩家声明、混淆私密消息和公开知识。

## 6. 跨局战略多样性（非旧候选评分器）

- Host 保存**实际采纳而非 AI 最初推荐**的关键首夜/后续配置，包含 Drunk 实际与展示身份、信息组合的角色/邻接关系/距离/阵营结构、明确注册决定、Red Herring、Demon bluffs、参与玩家/经验、适用剧本和人数、主要结构性张力。仅有候选提议不得记成已发生。
- 优先复用已存在的 setup rotation / archive 数据，增添**可用的实际线索战略记录**；旧 `HistoricalClueSignature` 是原型，不等于生产完整记忆。别另建一套独立 Game State。
- 首夜挑出近期**同剧本/相近人数/相同参与者**的相关 3–5 局（初始目标），提供少量结构化经验摘要。后续同局夜晚沿用该对话内历史，不逐夜重送。储存数、摘要 token 数是可调实验参数，不是硬性规则。
- **结构去重优先于字面去重**：仅更换座位编号或数字不一定构成全新体验；比较酒鬼角色/信息锁定图、登记歧义使用方式、恶魔伪装的配合模式、同一玩家重复承压等，而非机械轮换镇民。
- 多样性为**软约束**，劣后于规则、当前局公平/推理性、多夜因果一致性与当前玩家体验。AI 联合评估，不用 Host 相似度打分选最小值，不固定角色轮换，不因去重强迫不合理线索。
- 一局内需要保留醉酒线索等叙事**因果一致性**；同样结果可重复，不能把“本局跨夜一致性”误用为“必须与上一夜不同”。跨局经验不能泄漏成新局真实阵容。

## 7. 当前真实代码差距（2026-10-15 源码审查）

- 截至 Draft #308 commit `f09a2573`，Android V2 首夜采用 `store:true` Responses，Host 采纳后保存 response_id，后续以 `previous_response_id` 续接；这一首版已通过 CI/R2/Kotlin fixture，尚未真机或跨夜证实有效延迟与战略质量。普通不续接的 transport 构造仍可生成 `store:false`，不能因此误判生产链未接通。
- **新路线与生产代码存在明确差距**：当前 `StorytellerStrategicContinuationV2` 仍要求一次返回完整 `remainingChoices` 联合整包；新批准的运行合同要改为“复用有效缓存 / 无模型裁量不调用 / 需要时仅返回当前一项直接语义结果”。已有 P1 保留完整 Host 快照重发，尚无持久事件差量游标、基于魔典事件的通用推荐缓存失效、完整人工覆盖 fork / 恢复。战略记忆仍较短。
- APP 当前未有完整的长按座位公开声明/私下掩饰意向事件 UX、跨局结构性战略经验输入。首夜 `recentGames` 形参存在，但生产调用没有实际传值。
- V1 付费单点推荐路线已从 #307 删除并经 CI/R2 检验，不能因为新合同也是“单项结果”便恢复旧式角色单独分析。唯一全局战略引擎、连续 Responses、真实 Host 事实账本保持不变；Host 共用的 V1 后缀规则 DTO/数据结构不因名字包含 V1 就删除。

## 8. 验证与退出条件

1. **V1-RETIRE-NOW**：审查隔离补丁，确认生产仅有统一 V2 开局 + V2 续规划模型入口；旧模式无暗门；丢失 V2 依据时安全人工接管。获得 Android 编译、适当测试及独立 CI/R2，不将未经编译的补丁合并。
2. **AI-CONVERSATION-1**：同一 8 人局首夜→第一天提名/投票/处决/声明→第二夜 Host 合法多候选，验证 `previous_response_id`、是否有推理复用能力、记忆/事实一致性与每回合费用。对照 `current_turn` / `all_turns`（仅在模型支持时）与完整重算。
3. **AI-EVENT-JIT-1（替代旧 AI-DELTA-1 后续整包合同）**：验证配置确认后立即全局规划、AI/手动决定进入相同魔典事实账本；已有合法且战略前提仍成立的推荐无需请求；无缓存/人工覆盖/实质变化则按需只请求当前一个直接语义结果，并由 Host 校验。核对响应锚点以来的全量事件无缺口、无重复；未采纳分支不推进 canonical head、被拒结果只作建议不作事实；过期/并行回答/崩溃安全恢复；Host 唯一结果无模型调用，支持合适的提前预取。
4. **PLAYER-CLAIMS-1**：公开与私下声明权限/可见性、改口事件、重开局/恢复与 UI 长按审查；注入声明后没有未授权模型请求。
5. **CROSS-GAME-STRATEGY-1**：相同与不同玩家、相似但座位轮换的连续多局，识别结构性雷同且不牺牲公平；无需新加权特例。
6. **FIELD + quality**：多晚、多角色、投毒、Drunk/no-Drunk、Recluse/Spy 登记歧义、自动模式、ADB real Luna、费用/延迟、离线人工、恢复；保持统一 #315 Draft 直到实证通过；旧 #307 已关闭、其提交仍属于 #315 祖先。

## 9. 决策状态和范围

**批准**：确定阵容马上启动初始全局联合规划；所有实际决定进入 Host 魔典/游戏记录，与 AI 推荐是否采纳无关；逐个裁量点优先复用仍有效的预推荐，否则以连续对话 + 必要事件增量仅请求当前一个合法结果，仍保持全局战略分析；人工覆盖与真实动作触发通用有效性检查；合理预取、Host 完整合法性核验及事实权威。持续支持玩家声明、跨局软去重与旧 V1 付费单点路线退役。**被替代**：以后每次必须输出完整 `remainingChoices` 整包的旧强制要求。

**待实验决定**：当前部署模型的 persisted reasoning 有效模式、server conversation 保存/恢复策略、摘要压缩阈值、跨局保留长度和玩家身份长期 ID。不能因为 API 有能力就宣称该型号和 Android 产品已经有能力。

**不在本轮**：训练模型、旧加权排序器、强制 5 秒延迟承诺、任意多年未完局存档、跨版本迁移或不受限地储存/外传玩家私聊。

- **产品风险：语义合法不代表达到“首次全局联合规划完整信息预选”体验。** 因现有 Host 合同对状态可能受 Poisoner 影响的信息一律标记 `DEFERRED`，模型按合同无法给出其余 6 项的提前建议。这是模型输入/输出合同与预规划时机之间的系统性缺口，不要做“Poisoner 特例”或重新拆成 Drunk-only 调用。后续设计应通用地区分可撤回的**私有条件性预规划**、Host 事件落地后的最终合法选择、已对玩家公布的不可逆事实；所有未决因素用同一事件→事实→缓存有效性→当前单项全局战略裁量流程处理。P15 缺少全部首夜确定信息的缺口已被批准暂缓，不作为进入 AI-EVENT-JIT-1 的阻塞项。

- 该测试**不检验**投毒行动后重新规划速度、信息实际值、Android 实机采纳或多夜一致性；这些需要单独证据。不要从 P15 推断已经完成自动说书人。

## 11. AI-EVENT-JIT-1 下一实施切片（取代旧后续整包合同）

**总体约束**：首次仍联合、全局、只调用一次；后续输出最小化为**一个当前决策结果**，思考范围绝不最小化。不是对旧 V1 单项推荐器改名，不得新建平行 Game State 或针对 Poisoner / Fortune Teller / Undertaker 分裂不同 AI 算法。先复用现有 Host 原始事件日志、魔典决策/观察、RuleDomain 与候选转换器。

### 11.1 事件账本与推荐缓存

- 每项真实结果按现有 Host 事实提交路径落地：`decisionId`、`gameId`、阶段/轮次、事件全局序号与 revision、决定类型、真实选择及其来源（`AI_ADOPTED` / `MANUAL` / `HOST_RULE`）、是否私有/已发布、相关见证已证实还是未定。Drunk、红鲱鱼、Demon bluffs、信息与每次人工覆盖都遵守同一事实原则；**不得把未采用的推荐当成实际游戏事实**。对现有无法完备建模的角色，先识别账本缺口，不凭空假定所有决策已被录入。
- 独立的**未发布建议缓存**只保存 AI 候选、目标 `decisionId`、提出时 Host revision/事件游标、合法候选域指纹、依赖/适用前提、方案状态、关联战略记忆版本；不等于 Host 的已提交线索。已发布线索只读并由事实账本管理。
- 当有人修改过此前推荐、实际角色状态变化、角色结果被公布、关键声明/事件新增时，基于**通用依赖检查**复核缓存。模型已经返回的结果可能仍规则合法却战略已不合适；无法证明仍有效时保守失效。无关事件不得强迫每一项重新调用。
- 旧酒鬼提议被否决而改由 Host 指定另一位时，历史必须明确是“提议被拒”与“实际选择已提交”。后续新请求从合法对话锚点补齐中间记录，模型不得以旧假设为现状。

### 11.2 当前决策的极简合同

- Host 仅为**当前一项**真实待裁量的决策生成 `decisionId` 与语义需求；内部自行计算完整合法域，先判断玩家可见的合法结果是否唯一，唯一则直接确定而无付费模型请求。**不必把 Host 的候选枚举或 candidateId 发送给模型**；涉及 Spy/Recluse 的登记多义仍由 Host 判断，不让模型猜尚未确定的见证。
- 模型只返回机器可解码 JSON：绑定当前请求的 `requestIdentity`、事件游标/版本、`decisionId`、**一项直接语义结果**（数字、真假、角色名、座位对等）及必要的简短战略记忆；**不返回 `candidateId` 或 `remainingChoices[]`**。解码不等于规则合法：Host 在采纳/公布前独立检查状态、规则、登记多义、可呈现性及并发版本。
- 仅有合法候选不够：要同时检查当前局 ID、`stateRevision`、`playerInputRevision`、事实 cursor、角色/阶段/轮次、缓存失效 token、候选的完整语义与实际可呈现性。旧回复及并行旧请求不得写入事实、覆盖新推荐或推进锚点。

### 11.3 响应锚点与事件增量

- `canonical` provider head 只指向经 Host 校验且**已采纳**的方案节点；未经采纳、过期、错误的请求不推进。对话产生未采纳的模型私有分叉可保留为调试证据，但下次必须续接上一个可确认节点，或从完整 Host 快照恢复。
- 每个确认节点保留它看到的最后事件序号，下一次给出**从该序号到当前**的全部事实事件（包含全部确认提名、逐人投票及人工选择，而不仅是 AI 推荐）。事件的去重、排序、权限与缺口校验由 Host 完成；“上一条物理 HTTP 请求”不是可靠游标。还没有可恢复链时，使用当前完整 Host 真相和短战略锚点重新启动，不重发不确定的假设。
- AI_ASSISTED 的当前候选只作为未提交建议，直到用户明确采用；AI_AUTOMATIC 先走 Host 校验/安全私有预选，不得直接给玩家公布或跳过 UI/规则约束。
- `store:true` 的数据留存及可能重复计算的历史 tokens 保持透明，实测后再压缩上下文；失败不自动付费重试。

### 11.4 验收场景（行为证据优先，不机械增加无意义测试）

1. 开局身份配置已确定立即启动**一次**全局请求，逐人展示身份可并行；首夜结果真正采纳后 Drunk 等进入魔典，人工选择同样记录。无未来行动不得冒充已经发生。
2. 当前角色已有合法且战略前提未变化的推荐 → **不发送** API 请求，直接展示已有推荐；即使游戏账本新增了与之无关的事件也一样。
3. 前序 AI 建议被人工覆盖或状态变更 → 确认受影响缓存失效；到真正需要下一条信息时才发**一次**增量续接请求，返回**仅当前一个**合法候选。无缓存也同样按需请求。
4. 共情者 `0/1/2`、中毒占卜师 `有/没有`、送葬者一个合法角色名、成对证据两个座位/角色等，均由 Host 合法候选到 UI 的通用映射实现；**不为这些示例写模型策略特例**。
5. 玩家可见合法结果唯一 → Host 直接确定；失效、并行回复、拒绝的原建议、模糊见证及游戏恢复不可污染事实或 canonical 对话锚点。
6. 在合法事实已经稳定、下一项必需信息可知时可后台预取，但跳转、手动覆盖或新动作一旦令请求过期立即作废；实测调用数量、网络耗时、每次 tokens、缓存命中率与 Android ADB 体验。

**阶段收口**：先做现有账本/调用/结果显示链的代码审计，再实现最小 Host-owned 当前单项合同和缓存生命周期；独立 Android CI/R2 + 真机证据通过后才考虑合并。15 人局“所有首夜线索都提前确定”的旧缺口**暂缓**，不得因此阻挡 JIT 的正确性。
