# AI-STORYTELLER-CONTINUITY-1 — 连续对话、人工覆盖、玩家声明与跨局战略记忆

> 产品设计定稿：2026-10-15（Australia/Sydney）。状态：**架构目标已确定，API/模型细节与产品质量仍须实测；不是生产实现验收**。
> 当前任务入口：[roadmap](CURRENT_DEVELOPMENT_ROADMAP.md) / [handoff](NEXT_DEVELOPMENT_HANDOFF.md)。旧 3E/3E2/3E3 文档是各阶段的实现证据，不能覆盖本文件的新产品目标。

## 1. 单一专家说书人的产品目标

- **每局游戏只有一条持续演进的 AI 战略对话**：开局联合考虑真实与展示阵容、玩家经验、善良信息生态、邪恶压力与可维持的伪装、多夜可能发展；AI_ASSISTED 与 AI_AUTOMATIC 使用同一个策略控制器。
- 首夜只推荐**一套完整联合配置**（若本局有酒鬼，则酒鬼与该酒鬼的首夜线索、其他信息、红鲱鱼、恶魔掩饰身份同轮权衡）。**绝不为酒鬼先单独发一次请求，再重算首夜**。
- 已考虑但没有输出的模型推理可能有战略价值；尽可能验证 Responses 连续对话及兼容模型的跨轮推理复用，但它**不是 Host 事实、不是可阅读的完整思考存档，也不是无需验证的稳定长期记忆**。
- Host 持有唯一规则与 Game State 权威；产生合法当前候选、确认事件与历史、判断何时可裁量及何时公布。AI 只选择当前合法范围内最合适的**整组剩余决定**，不能生成未发生的行动、唯一注册见证、预设未来玩家选择或修改已公布结果。
- 追求两边公平、可推理且多种世界并存；照顾新手邪恶玩家实际能持续扮演的伪装，同时保留善良方可理解的检验线索。不以某一方必胜为目标，也不把盲测例子做成规则特例。
- 不随每次开夜单独重新从头规划，不引入各角色或各事件专属 AI 调度，也不复活旧加权、逐项排序器或 V1 单点推荐。

## 2. 三层记忆与唯一真相

| 层 | 权威与生命周期 | 用途 |
| --- | --- | --- |
| **Host 局内事实账本** | 唯一权威，事件溯源/单调序号；保存实际角色/展示身份/状态/规则登记裁定、玩家已收到的线索、提名/投票/处决、人工修改和有来源的声称；可恢复 | 从模型建议中区分**已执行、未采用、尚未公布、撤回/纠正**；不把猜测升级为事实 |
| **同局 AI 对话与战略假设** | 由已确认的对话锚点延续，依赖 Host 输入与 provider 可用性；允许修订/淘汰旧意图 | 记住开局信息锁定风险、可疑登记的不同世界、善恶压力、预备伪装、多夜线索意图及变化缘由 |
| **跨局战略经验库** | Host 本地长期存储；以完成/已实际执行的对局记录为准 | 对新局提供相关的结构化过去配置与套路摘要，避免熟悉玩家反复遇到近似体验；不把旧局对话拼接为新局身份或事实 |

正常路径：首夜输入完整；后续请求只送**自上次已确认对话节点以来的新增事件 + 当前阶段/轮次 + 此刻全部开放合法决定**，不再逐夜重发全部历史。API 续接期间仍须携带稳定简短的顶层说书人指令和严格 JSON 输出合同。Host **永久掌握事实**，不把服务端对话当作唯一存档。

## 3. 连续 Responses 协议（待实现与真 API 证实）

- 为每个 gameId 建立一条逻辑上的 Responses 续接链；保存**最后 Host 确认可延续节点**的 response_id、模型家族、协议版本、Host 事件序号/各 revision、已接受/公布的决策标记。
- 在可靠的 API 支持下使用 `previous_response_id`，正常夜晚仅新增因果增量与当前合法联合裁量。原型先研究 Responses 链；Conversations API 或 `store:false` 加完整/加密推理历史重放是备选，**不能把现有 `store:false` 当成已实现的 server-side 续接**。
- 遵守 provider 当前的数据保留、对话与模型支持限制。长于两小时的游戏不应因“时长”自动切断；受限于 response 保留/失效、context token 与费用，而非局内游戏时间。当前 ≤4 小时意外关闭恢复范围仍按既有产品决策，不在本路线扩展。
- 需要**实测**当前 `gpt-6-luna` 是否支持 `reasoning.context = all_turns`、返回的 effective 模式和跨轮行为。官方文档列出某些支持的模型家族不等于我们部署的具体模型必然支持。若不支持或无明显收益，则依赖显式短战略记忆，**不可冒充已保存模型内部推理**。
- 内部推理不作为可读取的长篇 chain-of-thought；不向用户/日志承诺显示其原文。保留可检查的简短战略锚点（主要张力、条件意图、待确认事实、明确的修订依据）是独立保险。
- 记录逐请求的实际 `input_tokens` / cached input / `output_tokens` / reasoning tokens（如 API 可得）、耗时、请求失败和剩余 context；历史上下文**仍可能在后续请求计费**，增量传输并不等于零成本。优先衡量质量，再根据实测选择压缩/摘要，禁止无证据声称 5 秒内重规划。
- **上下文分叉安全**：过期响应、未采纳方案、并行回应不得推进唯一 canonical conversation head。手动覆盖需明确区分原提案和实际采用；必要时从最后已确认锚点 fork，并注入 Host 最新事件。失败后支持事实账本 + 精简战略锚点的恢复，恢复时丢失隐性推理要如实标记。

官方参考（实现前复查最新）：https://developers.openai.com/api/docs/guides/conversation-state ；https://developers.openai.com/api/docs/guides/reasoning 。

## 4. 通用事件 → 决策流程

```text
Host 角色/状态/行动/信息公布/玩家声明/人工覆盖
    -> 一条不可变、有来源、附阶段轮次与序号的事件
    -> 更新 canonical facts / allowed decision scope
    -> 没有当前合法裁量：只记事实；无需 AI 调用
    -> 有当前需要判断的多个玩家可见合法结果：
         冻结 Host snapshot + 增量事件 + 全部当前仍开放的联动决定
         -> 继续同局 AI 对话，一次返回完整 remainingChoices
         -> Host 校验整包候选/语义/revision/事实序号
         -> 人工采纳或满足自动条件的安全私有采纳
         -> 实际 Host 提交/公布后才进入已执行事实
```

- **人工覆盖是一等公民**：说书人可以否决 AI 推荐的酒鬼，也可先采纳酒鬼、再手动改其中一条后续线索。已确认/公布的选择成为约束，AI **联合重新规划全部仍开放且受影响的剩余决定**，不重选已公布内容。
- AI_ASSISTED 应允许“确认/修改若干项→统一重新规划”，而不是每点一次就额外收费；AI_AUTOMATIC 走同一管线，整包严格核验后才能向 Host 提交。无法确认多义登记、当前候选或语义时暂停、人工接管。
- 玩家角色合法结果若对玩家**只有一种可区分的可见语义**，Host 可以确定并记录，不能为了得到另外的登记见证或制造差异强行请求 AI。
- 事件驱动**不等于每个事件调用一次 API**；提名、投票、处决、状态变化、声明先积累，到真正存在可裁量的开放决定时提交增量。所有角色、日夜、声明与手动改动适用同一机制。

## 5. 玩家身份声明和邪恶掩饰意向

- 在座位头像**长按**进入轻量选择器：先选记录类型，再选角色。
- `PUBLIC_CLAIM`：玩家在公开场合声称某角色；记录 sourceSeat、claimedRoleId、阶段/轮次、Host 记录时间/序号、公开范围（若未知显式 UNKNOWN）。**公开声称不等于真实身份**。
- `PRIVATE_BLUFF_INTENT`：玩家私下告知说书人希望扮演的身份；标记为意向，不能自动视为已经对全场公布。不要将其传成所有玩家都知道的事实。
- `CLAIM_CHANGED` / `CLAIM_RETRACTED`：变更/撤回追加新事件，不覆盖原历史；允许多项并存、互相矛盾、信息来源不完整。
- Host 将这些标记加入经过来源标注的事实账本；它们影响信息生态与掩饰可维持性，但只是玩家言论/意图，**不自动触发模型调用**。不能编造玩家声明、混淆私密消息和公开知识。

## 6. 跨局战略多样性（非旧候选评分器）

- Host 保存**实际采纳而非 AI 最初推荐**的关键首夜/后续配置，包含 Drunk 实际与展示身份、信息组合的角色/邻接关系/距离/阵营结构、明确注册决定、Red Herring、Demon bluffs、参与玩家/经验、适用剧本和人数、主要结构性张力。仅有候选提议不得记成已发生。
- 优先复用已存在的 setup rotation / archive 数据，增添**可用的实际线索战略记录**；旧 `HistoricalClueSignature` 是原型，不等于生产完整记忆。别另建一套独立 Game State。
- 首夜挑出近期**同剧本/相近人数/相同参与者**的相关 3–5 局（初始目标），提供少量结构化经验摘要。后续同局夜晚沿用该对话内历史，不逐夜重送。储存数、摘要 token 数是可调实验参数，不是硬性规则。
- **结构去重优先于字面去重**：仅更换座位编号或数字不一定构成全新体验；比较酒鬼角色/信息锁定图、登记歧义使用方式、恶魔伪装的配合模式、同一玩家重复承压等，而非机械轮换镇民。
- 多样性为**软约束**，劣后于规则、当前局公平/推理性、多夜因果一致性与当前玩家体验。AI 联合评估，不用 Host 相似度打分选最小值，不固定角色轮换，不因去重强迫不合理线索。
- 一局内需要保留醉酒线索等叙事**因果一致性**；同样结果可重复，不能把“本局跨夜一致性”误用为“必须与上一夜不同”。跨局经验不能泄漏成新局真实阵容。

## 7. 当前真实代码差距（2026-10-15 源码审查）

- 生产工作分支当前 V2 首夜 `InitialJointOpeningDirectV2` 和局内 `StorytellerStrategicContinuationV2` 已有严格 Host 边界；`PersonalDirectOpenAiV1.buildRequest` 仍 `store:false`、每次独立请求，未保留 response_id/隐性推理/连续对话。
- V2 continuation 当前重发大量全局状态与历史，AI 截断式 `strategyMemory` 较短，未实现事件差量续接、持久会话锚点和被拒提案的模型支线管理。
- APP 当前未有完整的长按座位公开声明/私下掩饰意向事件 UX、跨局结构性战略经验输入。首夜 `recentGames` 形参存在，但生产调用没有实际传值。
- V1 **立即退役**是已批准目标，不再等新引擎 parity。2026-10-15 Mini MCP 隔离工作树已生成移除旧 Drunk-only、postcommit、one-shot、逐项 fallback 的清理候选；**未提交到当前工作分支、未编译验证/未取得 CI/Android 验收**。完成审查/编译/独立 CI 后才可称“已退役”。Host 共用的 V1 后缀规则 DTO/数据结构不因名字包含 V1 就删除。

## 8. 验证与退出条件

1. **V1-RETIRE-NOW**：审查隔离补丁，确认生产仅有统一 V2 开局 + V2 续规划模型入口；旧模式无暗门；丢失 V2 依据时安全人工接管。获得 Android 编译、适当测试及独立 CI/R2，不将未经编译的补丁合并。
2. **AI-CONVERSATION-1**：同一 8 人局首夜→第一天提名/投票/处决/声明→第二夜 Host 合法多候选，验证 `previous_response_id`、是否有推理复用能力、记忆/事实一致性与每回合费用。对照 `current_turn` / `all_turns`（仅在模型支持时）与完整重算。
3. **AI-DELTA-1**：测试增量序号无缺口，重试无重复事件，手动替换酒鬼或先采纳后修改第一条信息后正确联合规划未公布余量，不污染已公布事实；失效响应/并发分叉和人工接管。
4. **PLAYER-CLAIMS-1**：公开与私下声明权限/可见性、改口事件、重开局/恢复与 UI 长按审查；注入声明后没有未授权模型请求。
5. **CROSS-GAME-STRATEGY-1**：相同与不同玩家、相似但座位轮换的连续多局，识别结构性雷同且不牺牲公平；无需新加权特例。
6. **FIELD + quality**：多晚、多角色、投毒、Drunk/no-Drunk、Recluse/Spy 登记歧义、自动模式、ADB real Luna、费用/延迟、离线人工、恢复；保持 #307 Draft 直到实证通过。

## 9. 决策状态和范围

**批准**：连续对话优先、Host 真相 + AI 战略双权威边界（只有 Host 是事实权威）、事件差量、覆盖后重规划、玩家声称 UI、跨局软去重、立即拆除 V1 单点路径。

**待实验决定**：当前部署模型的 persisted reasoning 有效模式、server conversation 保存/恢复策略、摘要压缩阈值、跨局保留长度和玩家身份长期 ID。不能因为 API 有能力就宣称该型号和 Android 产品已经有能力。

**不在本轮**：训练模型、旧加权排序器、强制 5 秒延迟承诺、任意多年未完局存档、跨版本迁移或不受限地储存/外传玩家私聊。

## 10. P15 首夜真实 API 实验（2026-10-15，独立实验分支）

- 实验 `botc-p15-standard-opening-20261015`，immutable plan SHA-256 `7c392fcb73d0a5697b4493fc14996be9257c94ab892bf34c52c0c2dce557efb6`，只授权并执行 **一次** `gpt-6-luna` Standard（`service_tier` 不指定）API 调用，无重试。Mini MCP 确认 HTTP 200、completed、原始响应已完整保存，用户估算授权上限 US$0.10，实际成本需按账单核对。
- 实际观测：约 34.5 秒；输入 6,344 tokens、输出 2,651 tokens（含 reasoning 1,140），按实验保守单价估算 US$0.00325705，**并非实际账单**。Mini MCP summary 的 `hostSemanticValidation: NOT_RUN` 仅描述其内部机械结果，**生产 Kotlin Host gate 在独立 GitHub CI 验证**，勿混淆。
- Kotlin 生产请求来自真实 `InitialJointOpeningDirectV2.encode` + `PersonalDirectOpenAiV1.buildRequest`，15 人、8 个合法 Drunk 分支、6 个首夜信息位，15 人经验均 BEGINNER；请求维持 `store:false`、无 Fast 参数。模型选 Drunk=4 Investigator；red herring=10 Undertaker；Demon bluffs=`soldier` / `slayer` / `mayor`。六个首夜信息位全部 `DEFERRED`（等待 Poisoner target，Fortune Teller 还等待双目标），无即时观察值。
- Host 逐字段的该 Drunk 分支合同比对无差异；真实输出另经 Kotlin `InitialJointOpeningDirectV2.decode` 的独立回归测试通过（`p15StoredRealLunaModelOutputPassesKotlinHostGate`，CI workflow `p1-wire-fixture.yml`）。没有修改生产源码、没有把模型提议当成已提交事实。
- **产品风险：语义合法不代表达到“首次全局联合规划完整信息预选”体验。** 因现有 Host 合同对状态可能受 Poisoner 影响的信息一律标记 `DEFERRED`，模型按合同无法给出其余 6 项的提前建议。这是模型输入/输出合同与预规划时机之间的系统性缺口，不要做“Poisoner 特例”或重新拆成 Drunk-only 调用。后续设计应通用地区分可撤回的**私有条件性预规划**、Host 事件落地后的最终合法选择、已对玩家公布的不可逆事实；所有未决因素用同一事件→事实→战略→剩余整包推荐流程处理。
- **策略质量待提高：** 酒鬼调查员有助于降低新手爪牙暴露压力，但当前战略摘要没有具体论及 14 号 Empath 邻接 13 号 Saint 与 15 号 Scarlet Woman、后续若清醒将取得对 15 号有压力的线索；亦未提前组合 Chef / Washerwoman / Librarian / Fortune Teller 的可能线索。不要误把合约允许的“全部 deferred”当作整局策略已经达到高质量。
- 该测试**不检验**投毒行动后重新规划速度、信息实际值、Android 实机采纳或多夜一致性；这些需要单独证据。不要从 P15 推断已经完成自动说书人。
