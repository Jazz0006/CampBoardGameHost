# 首夜推荐沿用与响应校验修复

本批基于 `4065d0fc`，包含推荐界面改动；提交、合并及远端 CI 状态以对应 PR 为准。

## 触发依据与最终处理

用户提供的 2026-10-25 logcat 显示：首次洗衣妇推荐为“7、8 号之一是处女”；到洗衣妇步骤再次请求，HTTP 200 返回相同选择，却因策略记忆 tensions 有 4 条而被本地三条上限拒绝。原沿用判断还会把间谍 NightWake 等正常首夜记录视为整份方案失效。

- 首夜间谍查看、管家选择主人保持原方案可用。投毒仅在改变尚未确认的信息依据时使方案失效；无关的士兵、僧侣等目标不触发。信息来源受毒，或推荐涉及的特殊认知受毒，仍失效；数值范围和认知能力由既有 Host 解析器判断。
- 酒鬼、红鲱鱼、恶魔伪装实际确认值偏离原方案，以及不同的已确认告知信息，保留失效保护。恶魔伪装按身份集合比较，不因排列顺序不同失效。其他机械变化保留原有保护。
- 图书管理员 ZERO_OUTSIDERS 使用完整的结构化外来者缺席集合比较；缺项、错误角色或其他命题不视为匹配。
- 首次和后续策略记忆共用现有模型中的三条/300 字限制。请求 Schema 明确数组 maxItems 与有界字符串 pattern，提示词同步。本地仍拒绝违规回复，不截断、不自动重试。
- 响应解析拒绝使用明确的异常分类，保留安全原因。四条记忆会指出字段、实际条数和上限；后续日志记为 HOST_REJECTED，不冒充 MODEL_UNAVAILABLE。界面失败详情显示当前错误全文，不显示旧理由。
- 现有 DEBUG 日志增加首次方案沿用/失效原因码；不增加凭据、额外游戏状态或持久诊断状态。

## 职责与验证边界

AI/UI 适配层判断方案沿用和已确认命题兼容；投毒的窄范围信息依据检查放在既有 HostInformationResolvers，读取唯一 Session。未新增规则候选引擎、第二 GameState、持久 pending 或独立恢复逻辑，Session API/JSON 和确认事务未修改。原请求键、过期响应检查、策略记忆/会话锚只在真实确认后晋升的路径保持不变。

已通过现有 `ClocktowerJointOpeningDisplayMatcherV2Test`、`InitialJointOpeningDirectV2Test`、`StorytellerStrategicContinuationV2Test`、`ClocktowerD2UiTest` 的定向验证，覆盖无关/相关投毒、匹配配置、零外来者及“间谍→洗衣妇不重复请求、Next 才记录”。仅补充上述具体故障的代表用例，不扩展人数/布局矩阵。

共用解析器的 `HostInformationResolversTest`、传输合同的 `PersonalDirectOpenAiV1Test` 及 Debug APK 构建也已通过。未运行完整套件。

Schema 约束依据：[官方结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)。尚未进行付费服务调用或真机重新验收；本地测试不等同于这些验收。

## 红鲱鱼页面接线与候选修复

- 将开局已接受、且当前仍有效的 `openingRecommendedRedHerringSeat` 传入红鲱鱼步骤，仅初始化本步 UI 草稿。手动模式不自动使用 AI 建议；取消或改选不会被再次预选覆盖。
- 根据 Session 的实际阵营和真实身份提供当前页面候选：善良玩家，排除隐士。排除隐士是用户指定的操作偏好，不宣称是游戏规则，不修改旧记录或 Session JSON。
- 预选、候选虚线、点击、Next 门槛及 UI→Session 确认边界复用同一份候选集合。无效推荐不进入草稿，不自动替换为其他人。仅 Next 确认最终选择；未确认改选不产生行动记录，也不推进 playerInputRevision。
- 首夜提示词同步说明善良阵营及排除隐士的偏好，避免模型继续推荐页面不接受的座位。
- 一个真实页面回归覆盖有效推荐预选、邪恶/隐士不可点击、取消/改选及最终只写一条确认记录；现有 Host 步骤、单目标呈现和首次返回解析用例通过。未新增像素、几何或人数矩阵测试。
