> **Historical-status note (added 2026-08-21):** Sections 7–8 below record the project state at the moment P1.3 closed. P1.1 and P1.2 were completed later the same day, and R6 P1 is now **CLOSED**. Do not execute the old “return to P1.2” instruction. See `CURRENT_DEVELOPMENT_ROADMAP.md` for the current status and `NEXT_DEVELOPMENT_HANDOFF_2026-08-21.md` for the current next step.

## 1. Scope

P1.3 required the project to stop using one ambiguous input shape for both actual storyteller truth and player possible-world construction:

```text
Actual FormalGameState
vs
Player-world construction input
```

The target was a type-level boundary, not a convention that callers would pass secret fields as `null` or simply promise not to read them.

## 2. Implemented boundary

### R6.5 — world-construction core

PR #7, merged as:

`19b91887344655285ec8bd93ca5bdb51bcfff445`

Introduced `KnowledgeSafeWorldInput` containing only:

- opaque `formalSnapshotId` version binding;
- `rulesetRef`;
- canonical structural `playerSeats` / derived player count.

The A3/A4 world-construction core now consumes this safe input. The `FormalGameState` overload remains only as a compatibility adapter and immediately projects to `KnowledgeSafeWorldInput`.

A PR review found that the first version accepted sorted/unique but non-contiguous seats even though the current enumerators generate `1..playerCount`. A regression test was added first and the input was hardened to require:

```text
playerSeats == 1..playerCount
```

This prevents a false-empty world set caused by pretending to support arbitrary seat numbering.

### R6.6 — player-knowledge construction core

PR #8, merged as:

`8f5ccc551948fea085caf8df3eb100ef67eae438`

Introduced `KnowledgeConstructionInput`, composed from:

```text
KnowledgeSafeWorldInput
+
explicitly public InformationProposition values
```

`A4PlayerKnowledgeFactory` safe-core overloads now consume this input for both already-bound observations and durable `EpistemicObservationLog` replay.

Durable observations can rebind using only the opaque formal snapshot ID, so replay no longer requires passing complete `FormalGameState` into the knowledge core.

The legacy `FormalGameState` overloads remain compatibility adapters only and immediately project to `KnowledgeConstructionInput`.

## 3. Information that cannot reach the safe cores through FormalGameState

The safe projection types do not expose:

- actual role;
- actual alignment;
- actual character type;
- poison state;
- shown role;
- storyteller-only propositions.

The knowledge-construction input additionally admits only propositions already classified as public by the formal layer. Direct public propositions are validated against the structural seat set.

The opaque formal snapshot ID remains intentionally available as a version/binding coordinate. It is not used as a world constraint.

## 4. Tests-first evidence

The P1.3 slices prove:

- changing secret player fields or storyteller-only propositions does not change the safe projection when the opaque version binding and public structure are held constant;
- changing an explicitly public proposition changes the knowledge-construction input;
- safe world construction matches the compatibility Formal adapter;
- safe player-knowledge construction matches the compatibility Formal adapter;
- durable-log replay through the safe path matches the Formal adapter;
- mismatched snapshot bindings fail closed;
- duplicate/unsorted/non-contiguous structural seats fail closed;
- public propositions referencing unknown seats fail closed;
- recipient validation is based on structural seats, not actual player truth.

## 6. P1.3 exit decision

P1.3 is **PASS** because the world-builder and player-knowledge construction cores no longer require or receive complete storyteller truth. Any compatibility path that starts with `FormalGameState` crosses an explicit one-way projection before reaching those cores.

This closes the original ambiguity without changing world enumeration semantics, player-world identity semantics, production Host flow, persistence schema, or recommendation behavior.

## 7. Remaining P1 blockers

P1 is **not** fully closed.

### P1.1 — OPEN

Spy Grimoire reminder-token mechanical-truth boundary remains to be finalized before production Spy-perspective reasoning.

### P1.2 — OPEN

The global timeline foundation, allocator/restore contract, durable observation binding, and knowledge chronology seams now exist, but production multi-night reasoning still needs the remaining timeline work to be closed explicitly. In particular:

- `ActionFact.sequence` is already global/unique inside its reducer but is not yet formally bound to the shared `TimelinePoint` authority;
- A3/ZDD/B4 contain legacy replay sorts that are harmless while the current evaluator is time-insensitive but must be migrated before historically time-aware evaluation;
- `globalSequence` intentionally remains outside `PlayerWorldSetIdentity` while world filtering itself is time-insensitive; that decision must be revisited only when timeline position changes world semantics.

Therefore production multi-night Possible Worlds remains blocked by P1.1/P1.2 even though P1.3 is now closed.

## 8. Next recommended slice

Return to **P1.2** with a narrow contract slice that binds the already-global `ActionFact.sequence` to the shared timeline authority without rewriting `DynamicActionReducer` or connecting production Host.

Tests should prove at minimum:

- action sequence and shared global timeline position cannot disagree;
- duplicate global positions fail closed;
- reducer ordering remains unchanged for valid migrated facts;
- restore/replay preserves the same committed action order;
- no local phase/round sequence is inferred into a global identity.

Only after that contract is stable should the A3/ZDD/B4 replay sort be migrated for future time-aware multi-night evaluation.
