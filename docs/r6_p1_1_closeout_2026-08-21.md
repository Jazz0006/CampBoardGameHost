# R6 / P1.1 Spy Grimoire Truth Boundary Closeout — 2026-08-21

## Decision

**P1.1 semantic prerequisite: PASS.**

The repository now has an explicit, rule-backed boundary between a legacy player-facing Spy Grimoire display and a mechanically authoritative physical Grimoire snapshot. Reminder-token identity is typed and resolved from the active validated ruleset; exact world filtering is enabled only for propositions produced from a complete explicit physical snapshot.

This PASS does **not** mean production Spy reasoning or production multi-night Possible Worlds is enabled. Production Host/Compose remains intentionally outside this closeout and still emits legacy display-only Grimoire propositions. A future rollout must first establish a durable authoritative physical-truth producer and prove that it is complete.

## 1. Problem closed by P1.1

The original P1.1 risk was that Spy-visible reminder tokens could be treated as trustworthy mechanical facts without a provenance contract.

That was unsafe for several reasons:

- arbitrary UI/display strings are not ruleset-backed token identity;
- duplicate printed reminder labels may represent distinct physical token occurrences;
- the current runtime `GameState` does not contain every physical Grimoire fact;
- player-facing shown role and the physical character token cannot be assumed to remain synonymous for every future mechanic;
- a missing reminder list in a legacy proposition cannot be interpreted as proof that no reminder token is physically present;
- the current Trouble Brewing world model can represent only a subset of visible reminder semantics exactly.

P1.1 closes this by making truth provenance explicit and fail-closed rather than guessing from incomplete runtime/display state.

### R6.16 — explicit physical Grimoire truth projection seam

PR #20 merge: `1a2b1852c77473e525535377afe70186da26700e`

Established:

```text
ValidatedClocktowerRuleset
        ↓
explicit physical snapshot input
        ↓
SpyGrimoireTruthProjector
        ↓
InformationProposition.GrimoireState
```

The projection input is explicit rather than reconstructed from incomplete runtime state:

- independent `expectedSeatRoster`;
- one `GrimoireSeatTruth` per expected seat;
- physical displayed character token;
- alive state;
- rule-backed reminder placements expressed as target seat plus source-role/scope/occurrence identity.

The projector resolves reminder tokens through the active validated ruleset at projection time. It rejects:

- sparse or extra seat truth;
- duplicate seats;
- off-script reminder sources;
- unsupported displayed roles for the currently validated registry;
- one physical reminder occurrence placed on multiple seats.

Review found that the initial exact snapshot shape could omit a seat and silently under-constrain downstream filtering. The fix added the independent expected roster and exact set-equality validation tests-first.

Deliberately **not** implemented:

- `GameState -> GrimoireState` inference;
- Host/Compose wiring;
- automatic reminder-placement inference.

### R6.17 — audited exact world constraints and provenance split

PR #21 merge: `f77338bc85ae4a81b7e54e456b430e2f7f35c51a`

R6.17 introduced the final prerequisite distinction:

```text
GrimoireTruthBinding
├── LEGACY_DISPLAY_ONLY
└── VERIFIED_EXACT
```

`VERIFIED_EXACT` is emitted only by `SpyGrimoireTruthProjector`, whose input must already represent a complete explicit physical snapshot. Existing constructors and old schema-v2 payloads remain `LEGACY_DISPLAY_ONLY`.

The shared Trouble Brewing evaluator now applies different semantics by provenance:

- Legacy propositions retain the existing displayed-role/alive compatibility behavior;
- Legacy empty reminder data is **not** interpreted as exact absence of physical reminders;
- VerifiedExact propositions require complete roster coverage and may constrain physical role tokens and audited reminder mechanics;
- provenance participates in proposition equality/canonical identity;
- Legacy JSON keeps the previous shape by omitting `truthBinding`;
- missing binding decodes as Legacy;
- VerifiedExact persists explicitly as `truthBinding: "verified-exact"`;
- explicit null or unknown bindings fail closed.

## 3. Audited exact reminder semantics

The current Trouble Brewing possible-world model can exactly consume only reminder semantics that are both officially audited and represented by current world dimensions.

R6.17 therefore constrains only:

1. **Drunk — `IS THE DRUNK`**
   - physical Townsfolk character token plus the Drunk reminder identifies the Drunk world fact;
   - physical token truth is not taken from player-perceived `shownRolesBySeat`.

2. **Fortune Teller — `RED HERRING`**
   - the reminder constrains the selected good Red Herring player represented by the current world model.

3. **Poisoner — `POISONED`**
   - the reminder constrains the current Poisoner target while the Poisoner is alive;
   - targeting the already-Drunk player remains distinguishable under the current single `AbilityState` representation;
   - a dead Poisoner on a later night does not create a current Poisoner-target reminder requirement.

A recognized mechanical token identity paired with a spoofed label fails closed.

Visible reminders whose mechanics are not exactly represented by the current world model, such as Monk `Safe`, remain visible but deliberately **under-constrained**. The evaluator does not manufacture precision by guessing semantics from labels.

## 4. Resulting semantic model

For an exact Spy observation, the supported path is now:

```text
ValidatedClocktowerRuleset
        ↓ rule-backed token identity
explicit complete physical Grimoire truth
        ↓
SpyGrimoireTruthProjector
        ↓
GrimoireState(VERIFIED_EXACT)
        ↓
audited exact A3/ZDD world constraints
```

The invariants are:

1. Ruleset-declared token identity is authoritative; UI strings are not.
2. Physical token occurrences are unique and occurrence-sensitive.
3. Exact truth must cover the complete expected seat roster.
4. Physical character-token truth is distinct from player-perceived shown-role state.
5. Only the explicit projector may promote a proposition to VerifiedExact.
6. Legacy display propositions are never silently upgraded to exact truth.
7. Exact filtering is limited to mechanics represented by the current world model.
8. Unsupported visible reminders remain explicit under-constraints rather than guessed mechanics.
9. Proposition provenance participates in semantic identity and persistence.
10. Malformed or ambiguous persisted truth binding fails closed.

## 5. Production cutover guardline

P1.1 PASS is a **semantic prerequisite result**, not a production rollout claim.

Still intentionally not completed here:

- production Host/Compose is not wired to `SpyGrimoireTruthProjector`;
- the current Host Spy producers remain Legacy display-only producers;
- production does not yet have a durable authoritative source for every physical reminder placement;
- current `GameState`, UI labels, or an existing empty reminder list must not be used to synthesize VerifiedExact truth;
- no automatic historical Grimoire reconstruction was added;
- no full multi-night historical world engine was added;
- B4 remains shadow-only;
- no recommendation-selection production path was switched to a new epistemic engine.

A future production VerifiedExact cutover must begin with an explicit audit of where complete physical Grimoire truth can be authored, committed, persisted and restored. If any required physical fact is unavailable, the producer must remain Legacy rather than inventing an exact snapshot.
