# R6 / P1.2 Timeline Identity Closeout — 2026-08-21

## Decision

**P1.2 semantic prerequisite: PASS.**

The repository now has one explicit game-wide timeline identity contract for timeline-aware epistemic work. Local phase/round/sequence fields remain replay/display context; `TimelinePoint.globalSequence` is the ordering identity. Legacy data is represented explicitly and is never silently promoted by guessing a global position.

This PASS does **not** mean production multi-night Possible Worlds is enabled. Production Host/Compose has intentionally not been cut over to global timeline allocation in this stage, and P1.1 Spy reminder-token truth boundaries remain OPEN.

## Resulting semantic model

For new globally timed semantic histories:

```text
ClocktowerGameSession allocator
        ↓
TimelinePoint(globalSequence)
        ├── ActionFactTimeline
        └── Global observation records
                 ↓
      shared chronology / uniqueness rules
                 ↓
       knowledge + A3/ZDD/B4 consumers
```

The invariants are now:

1. `globalSequence` is the only cross-phase/cross-round ordering identity.
2. Local sequence is never promoted into global identity by inference.
3. Legacy and Global migration states are explicit.
4. Global observations are homogeneous and globally unique within an observation history.
5. Global actions are globally unique within an action history.
6. Combined timeline-aware consumers reject action/observation global-position collisions.
7. Combined consumers do not invent an ordering between non-empty Global actions and non-empty LegacyLocal observations.
8. Persisted and in-memory timeline containers defensively protect validated history from caller-owned list mutation.

## Identity / cache decision

The current Trouble Brewing world evaluator is still **time-insensitive**: filtering depends on the proposition/mechanical world state, not the observation's historical timeline position.

Therefore P1.2 intentionally does **not** add `globalSequence` to `PlayerWorldSetIdentity`, and it does not inject global timeline position into recommendation stable-selection digests merely as defensive invalidation.

When a future evaluator starts interpreting observations against historical state, this decision must be reopened tests-first. At that point, any timeline field that can change the set of valid worlds must participate in the relevant identity/cache/digest contract.

## Production cutover guardline

P1.2 PASS is a semantic prerequisite result, not a production rollout claim.

Still intentionally **not completed** here:

- Production Host/Compose does not yet allocate every action/observation through the per-game global allocator.
- Existing running/legacy games remain LegacyLocal where applicable.
- No legacy save is silently upgraded by synthesizing historical global sequence values.
- B4 remains shadow-only; production recommendation selection does not depend on it.
- `TroubleBrewingWorldEnumerator` remains a setup/first-night constructor; P1.2 did not turn A3 into a historical-state engine.
- The current evaluator is not yet historically time-aware.

A future production global-timeline cutover must start a new globally timed game in Global mode from its first committed timeline event and preserve the allocator cursor across restore. It must not mix a partially migrated legacy game with guessed Global positions.
