# BMR-A：剧本与人工开局实施方案

**历史阶段说明：** A 的只读首夜开发预览现已被真实 MANUAL 流程替换，DEBUG 门槛及预览专属入口已删除。当前完整流程、人工裁定和验收状态见[最新交付](BMR_MANUAL_GAME_PROGRESS_2026-11-02.md)。下文保留 A 阶段原始范围与证据。

状态：2026-11-02，已按用户后续授权实施 BMR-A 开发预览，基于 `27cf84fc`；实现与验证见文末。原路线的 AI 异常/恢复后可人工续局任务仍未完成，完整 BMR 主持尚未实现。

## 1. 交付边界

BMR-A 完成：选择暗月初升 → 规则内随机生成角色/座位 → 主持核对或调整 → 核对展示身份 → 原子创建唯一 Session → 逐人私密发牌 → 进入首夜主持方桌；异常退出后可继续这局游戏。

这不是完整 BMR 可玩验收。多次攻击、复活、登记死亡、效果期限、特殊终局依赖 BMR-B；正确的 BMR 夜间交互依赖 C，白天特殊触发依赖 D。A 不允许把无处理器的角色静默跳过，或把空夜序解释为“首夜已完成”。

A 单独审阅时使用明确的开发预览入口/现有构建机制隔离 BMR，普通发行入口在可玩批次完成前不开放。优先用现有 build variant/BuildConfig 常量控制一个入口，不另造功能开关服务。进入首夜方桌可以查看布局、设置和记录；尚未接入的主持动作不可确认，显示简短“本批仅支持开局”的开发预览说明。不要实现假 Next、通用完成事件或第二个主持界面。若安全进入现有首夜 Host 必须依赖 C 的处理器，则 A 先保留共享只读方桌作为预览，不提前改造完整夜间执行器。

## 4. 随机生成与主持核对流程

保持已有座位确认与剧本选择。选 BMR 后，在最终发牌前增加人工阵容配置；TB/NGJ 的现有开局不增加步骤。

1. 选择 BMR 后，按人数及官方构成规则随机生成实际角色与座位分配，默认不要求逐个选角色。直接展示主持人私密核对表。
2. 提供“重新生成”和“调整阵容”。重新生成整个未确认布局；调整允许更换角色、交换座位，实时显示人数构成和错误原因，不在编辑中悄悄替换其他角色。
3. 若选中疯子，生成一项合法的恶魔展示身份，允许说书人调整；实际角色仍为 Lunatic、初始实际阵营保持正确。展示身份允许与真实恶魔相同，不套用实际角色唯一性检查。具体展示身份范围与必需的开局配置按官方规则核对，不凭空创造身份。
4. 最终核对表按座位列姓名、实际角色、必要的展示角色；点击“确认并发牌”才原子创建和保存 Session。未确认的随机结果只是开局草稿，不是事实记录。
5. 逐人交接沿用原发牌界面。开始前返回保留本次草稿，不能因重组 UI 再次随机；人数/座位/剧本改变时明确重新生成不再适用的布局。草稿无需跨进程恢复。

随机生成的最小实现：使用既有 seed/随机工具，按人数选出正确数量的恶魔和爪牙，再依据是否存在 Godfather 计算合法外来者数量选项，从合法选项中随机选择，随后无放回抽取外来者/镇民并随机分配座位。构成调整的范围和先后须以官方规则核对为准，不把本段当作规则原文。生成器与人工调整后的结果均通过同一纯开局校验；不能用无限重试随机不合法布局的方式代替构造合法结果。使用固定种子可复现；“重新生成”显式采用新种子，确认后的身份不再随机。

A 批只承诺规则允许的开局构成与必要身份配置，不承诺阵容有趣、均衡或从全部合法阵容严格等概率采样。不加入 AI、评分、世界枚举或自动淘汰差阵容。精品模板可后续补充，不是随机生成的前提。BMR 本批不增加跨局去重或角色轮换算法，现有 TB 两项历史行为不变。

### 必须由一个 Session 侧开局校验入口负责

草稿校验与最终创建调用同一套纯校验；UI 仅显示结果，提交时必须重新校验，防止旧草稿或直接调用绕过。

- 目标 5–15 人，座位连续、每人一个实际角色、角色属于 BMR、实际角色不重复、实际恶魔恰好一名。
- 人数构成采用官方分配表；Godfather 在场时允许官方规定的外来者数量调整，并对应调整镇民数量，实际总人数与爪牙/恶魔数量保持正确。不接受任意偏离构成的“说书人确认即可”。
- 5–6 人必须先核对 Teensyville 的开局及阵营信息规则，不能直接把 7 人以上的流程缩小。A 的最终人数验收目标仍为 5–15；未核对的范围不得先开放。
- 疯子的误认身份为允许的恶魔展示身份，不改变实际角色/阵营/人数统计；普通角色不能通过通用编辑任意改成另一种实际身份或阵营。
- 随机生成、模板与人工调整使用同一入口；此校验只做开局必要结构，不做阵容评分、规则世界枚举或强弱淘汰。

Godfather 的初始外来者调整属于 A；其后续死亡/额外击杀留给 B/C。Grandmother 的孙辈等首夜秘密配置在 C 的正确步骤确认，不在 A 中用未持久化的 UI 字段假装已经决定；A 只预留目录和明确的后续依赖。

## 5. 模式、隐私与异常续局

**用户再次明确的约束（2026-11-02）：存档只用于异常退出后尽快继续当前局，避免丢弃半局。** 本批沿用现有一个活动局文件和现有保存入口，完成最小 BMR 接入即可。

- 重新打开后加载最后一次成功确认的状态，进入当前主持流程；玩家、身份、阶段和已确认结果保持正确，不重复执行已确认操作。
- 未确认的选择、预览、弹窗和滚动位置可以重新操作，不要求恢复到退出瞬间的界面；未确认开局草稿可以重新生成。
- 不增加存档管理页面、多存档槽、历史版本、回滚、逐步回放、完整初始快照、导入导出、跨设备同步或通用迁移框架；这些都不是本次功能的后续待办。
- 已确认事件继续服务当前局流程与游戏记录页；不为了“能重演整局”额外记录所有中间操作。随机种子用于正常生成和必要测试，不承担从头重建游戏的责任。
- A 只核对开局中断后的最小续局链；B/C/D 随各自真实状态接入现有保存，不预先设计未来角色的恢复体系。


- BMR 使用 MANUAL，不要求模型、API Key 或网络；全局默认 AI 模式不改变。复用 `storytellerModeForNewGame()` 已有的非 TB 手动边界，不新增一套 AI 开局/后夜入口。
- BMR 创建前清理旧开局建议和请求归属，避免上一局 AI 返回值影响新局；不得把 BMR 当前状态送进 TB 联合开局解析器。
- 用实际角色/展示角色的现有字段表达疯子误认，不新加平行玩家模型。玩家卡、背景、文案和无障碍描述都只投影应展示的身份，不能出现真实“疯子”、真实阵营或其他主持秘密；主持私密方桌仍显示真实布局。
- BMR 最小开局保存优先沿用 Session JSON v1 字段，只扩展受支持脚本与角色校验；不在 A 提前加入 B 的复活/登记死亡模型。仅在实际续局需要且现有字段无法表达时增加必要字段，并说明当前受支持存档如何继续；不预建版本迁移平台，不自行把 B 的设计混入 A。
- TB/NGJ 原 v1 活动存档不变且可恢复；未知脚本、非法 BMR 构成仍报错，不能因放宽白名单而停止校验。
- BMR 通过既有 metadata 保存 MANUAL，不写 TB 的 rotation 或专有 rulesetRef。现有 TB 阵容/玩家身份防重复历史保留，不把 BMR 记录塞入 TB 数据集，也不新增跨局多样性算法。
- 发牌中断恢复沿用当前“未完成交接可重新交接”的合同，不增加逐人发牌持久游标；恢复后实际/展示身份必须一致，不重新随机分配或再建 gameId。
- 保存失败时不替换活动 Session、不进入发牌；配置返回/取消不生成对局事实。不新增初始布局快照或历史回放需求。

## 8. 本次实现与核对

- DEBUG 构建可选 BMR 5–15 人；普通发行入口不开放开发预览。随机生成合法实际角色与座位，核对页可重新生成、更换角色、显式交换已占用角色的座位和调整疯子展示身份；不加评分或跨局历史算法。
- Session 侧一个纯开局校验同时服务生成、编辑提示和最终提交。Godfather 在场时按合法的 -1/+1 外来者选项生成，镇民补齐总人数；疯子实际为善良外来者，展示为 BMR 恶魔。
- 官方 Setup 明确不推荐 BMR 少于 7 人；预览中保留 5–6 人但给出说明，不能把该范围宣传为推荐配置。首夜阵营互认与疯子夜间信息在 C 批处理，不在本批假确认。
- BMR 确认为 MANUAL，无需 API Key；复用逐人发牌和共享私密方桌。BMR 分支在进入现有夜间执行器之前返回，方桌不能推进阶段，也不调用 TB 的确定性结算。
- 沿用现有活动局文件、Session JSON v1 字段与 metadata 结构，只扩展脚本识别和 BMR 开局校验。恢复沿用现有未确认交接可重做行为，不增加发牌完成标记、UI 游标、初始快照、历史槽或迁移框架。TB/NGJ 的编码字段和恢复路径保持原状。当前 BMR 仅有开局，后续 B 批须按真实运行状态更新校验，不能把开局构成检查强套在角色已变化的中局。
- 新增两项有独立风险价值的行为回归：开局生成/教父增减/疯子真实展示身份与 Session 编解码；真实 App 无凭据开局、私密发牌、不可误推进及恢复后继续同局。没有新增像素、几何、人数×模式组合测试。
