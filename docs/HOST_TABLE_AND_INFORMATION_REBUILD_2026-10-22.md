## 0. 总目标与不可破坏边界

1. **全面替换旧视觉／交互规则，而不是旧 `SelectedFirst/SelectedHighlighted/RegistrationHint` 体系叠加新枚举。** 迁移完整生产消费者，删除旧高亮逻辑、旧独立选择页面和独占测试；保留已确认的统一方桌、物理座位布局、红蓝底色和必要的选择／虚线绘制底层能力。
2. **唯一可写 Session**：角色、真实阵营、存活、当前有效中毒、已确认鬼票、夜间动作、红鲱鱼、恶魔伪装、最终玩家信息与顺序事件均从 `ClocktowerGameSession/ClocktowerSessionState` 读取或确认。UI 临时草稿、信息候选、预览、高亮都不是独立游戏状态，不能持久化第二份状态或维持多路控制。
3. **最小 Host 规则职责**：Host 求确定性信息和真实登记裁量范围；AI 给说书人策略建议，不生成另一个规则权威。禁用旧广义候选/评分/一致性/世界枚举；新增求值只能只读、局部、纯计算，优先复用 `AbilityFunctioningSemantics` 与现有 Session 投影。
4. **D2 不变**：一条信息可以多次在同一步全屏预览并返回修改；**只有本步显式“下一步”才提交最后一次展示的唯一私密 Observation**。修改草稿使上一预览失效；不能跨角色“上一步”；意外退出允许当前步骤重新选、重新展示。不给信息预览追加“是否人工覆盖／来自 AI／中间登记选择”等冗余事实。
5. MANUAL、AI_ASSISTED、AI_AUTOMATIC 三模式都保留；AI 自动替代说书人裁量，不替代现场唤醒、手机交接和真人玩家行动。现有 AI 联合开局、后夜增量及战略记忆、两项跨局防重复保留。TB 5–15、NGJ 5–6、360×520 竖屏为设计边界。

## 1. 所有说书人方桌共用的玩家卡片

### 1.1 常驻层：只显示高价值当前事实

| 状态 | 新视觉合同 |
| --- | --- |
| 真实阵营 | 保留善蓝 `#24568D`、恶红 `#8F2D3D`，角色/玩家文字高对比；间谍/隐士登记不改底色 |
| 存活 | 正常阵营底色；不加多余“清醒”标记 |
| 死亡 | 阵营底色适度降饱和／暗化（仍辨得出善恶），清晰“亡”角标；**删除贯穿卡片的大叉** |
| 死亡且尚有鬼票 | 右下或下边缘醒目的金色投票圆点；只对死者展示 |
| 死亡且已用鬼票 | 取消金色标记；普通方桌无需再显示“已用”；投票页可按需用空心灰圆辅助 |
| 真正的 Drunk | 卡片内部紫色细色带 + 醒目的“醉”；真实身份来自 Session 而不是表面展示镇民 |
| 当前中毒 | 卡片内部黄绿色细色带 + 醒目的“毒”；根据 Session 有效期实时变化，解除后消失 |
| 同时醉酒和中毒 | 两侧内部色带 + “醉”“毒”，不能相互覆盖 |
| 身份变化 | 显示已确认的当前真实身份；历史变更通过详情或事件查询，不常驻旧身份 |

“整局持续”指**全流程统一规则**（白天、首夜、后夜、魔典等说书人私有方桌），不是使临时中毒永久生效。预览交给玩家的页面绝对不展示私有阵营、酒鬼、中毒、红鲱鱼、恶魔伪装等事实。

15 人常见卡片约 64×70 dp；小屏幕不新增单独的状态文字行。优先留足座位号、姓名、角色和当前状态的可辨认空间。色带与文字配合，不能只有颜色才能区分；不要动画、冒烟、粒子、发光特效或新的依赖。

### 1.2 外围操作层：只在当前操作中出现

- **普通真实候选目标**：金色长虚线外边框。
- **间谍／隐士有效特殊登记候选**：青色短虚线外边框，可附小问号；必须由**本次查询实际相关的座位、能力是否有效**决定，不能只因全局有间谍/隐士就显示。
- **已手选目标**：外部实线边框；两人有先后次序时用 ①/② 清楚标记。选中取代候选虚线，卡片阵营底色和内部状态仍不变。
- 虚线只是说明“可能支持当前真实线索／可帮助说书人选择”，**不是阻止点击非候选玩家的规则**。例如洗衣妇可以选“一个真实镇民 + 一个无关座位”。
- 原“当前唤醒者 4dp 粗金框”取消；中央醒目文字“唤醒 X号 · 角色”负责当前角色标识，避免抢占边框。
- 提名/被提名、待确认投票者、行动目标、连线等只在相关页面临时出现；其显示不得改变善恶底色、死亡／鬼票／醉毒内侧标记。

**三个层次独立组合**：阵营＋死亡／鬼票／醉毒为常驻内部事实；虚线为未选目标提示；实线为当前选中。不得恢复用一个巨型互斥 `SeatState` 枚举覆盖所有维度、由“更高优先级”把事实遮掉的旧设计。

### 1.3 不常驻的事实

僧侣当晚保护、占卜师红鲱鱼、管家主人、某次恶魔攻击／市长转移、圣女触发、已经使用杀手/艺术家技能、本日提名资格和投票草稿、间谍／隐士的单次登记、恶魔三个伪装身份等：**只在相关角色/阶段操作或详情中呈现**，不往每张小卡片叠加常驻图标。已使用能力由相关控件与 Host 事实决定；不得新造“卡片能力使用状态库”。

## 2. 统一夜间唤醒提示

所有角色在既有稳定方桌上唤醒，不新增 StartNight／单独唤醒页面。方桌中央：
- 正常：“唤醒 X号 · 角色”，不占空间另写“能力正常”；
- 酒鬼：额外醒目“真实身份：酒鬼”；
- 中毒：额外醒目“当前中毒”；
- 两者同时：同时明确提示。
这些仅为说书人私有提示，不能出现在玩家全屏展示。放弃上一版仅唤醒时冒烟动画，采用全局持续的卡片内侧标记。

## 3. Host Information Resolver 的小型只读边界

以 **唯一 Session + 当前交互/选定查询座位** 为输入；复用 `AbilityFunctioningSemantics`（信息能力提供者是否 Drunk/poisoned）、当前真实身份与展示身份、各被检查对象自身的有效登记能力、环形物理座位、死亡、必要夜间唤醒事实。

- `NumericInformationResolver` 仅负责四个 `NumericMetric`：`ADJACENT_EVIL_PAIRS`（厨师）、`LIVING_EVIL_NEIGHBOURS`（共情者）、`STEPS_TO_NEAREST_MINION`（钟表匠）、`PLAYERS_WAKING_FOR_ABILITY`（侍女）；现阶段先完整实现厨师、共情者，后扩钟表匠、侍女。
- 唯一真值返回单值；受有效间谍/隐士登记影响时返回可能结果集合；信息能力源醉酒/中毒时提供适合角色形式的可展示范围。**“规则允许的裁量”与“产品为了简单提供的选项”是不同概念，不得把产品短名单宣称为规则全部合法域。**
- 厨师计算环形全桌相邻邪恶配对（含末座到首座）；共情者计算两名最近**存活**邻居；钟表匠计算恶魔到最近爪牙的步距；侍女计算所选两人当夜**因自身能力醒来**的数量，不能简单统计已执行行动，需单独审计夜间唤醒定义。
- **信息角色本身失效**与**被调查的 Spy/Recluse 自身失效**分别判断。醉毒不能无条件把所有特殊登记打开；每次查询局部求值，不建立持久“注册阵营”或假设世界。
- `PairInformationResolver` 只根据当前两个座位和源能力状态返回精简角色选择、来源分区及“无外来者”特殊选项；不在开局预先生成全局“每角色 × 每两个座位”候选组合。占卜师布尔和其他身份查询将来按需复用底层事实语义，不强塞进数字/Pair 类。

所有 AI 推荐需根据同一 Session/查询进行有效性检查；规则求值不可覆盖已确认展示或创造二次 Observation。

## 4. 数字信息角色的统一方桌交互

厨师、共情者优先使用同一组件，后续钟表匠/侍女复用其**结果选择＋展示**部分，按能力增加目标输入。

1. 进入方桌唤醒；显示当前能力的可展示数字，单选 UI 而非旧任意非负数文本框；AI_ASSISTED 标记当前有效推荐。
2. 只有一个可用数字时，直接提供唯一“展示给玩家：N”按钮，**不显示冗余选项列表**；多个数字才呈现单选。
3. 按钮自身即预览，不再在上方重复一行预览文字；点击进入已有私密全屏展示。
4. 关闭全屏回同一步，保留刚展示数字；可重新选择、再次展示；修改后未重新展示不得直接 Next。
5. **Next 唯一提交最后一次展示 Observation**；不跨角色退回，不记录 AI vs 人工来源，不另设中间确认状态。

## 5. 洗衣妇／图书管理员／调查员 Pair 信息方桌

### 5.1 三模式入口

- `MANUAL`：直接进入同一方桌上的手动选择；
- `AI_ASSISTED`：当前一条、以后可扩为三条完整推荐（两个座位＋角色或特殊“0”），另有一个“手动选择”入口；
- `AI_AUTOMATIC`：仅展示已接受的当前推荐按钮（若无合法当前结果，保持等待／错误重试，不冒用不存在的固定答案）。
- 所有模式均需真实说书人交接手机、查看全屏玩家视图并显式 Next；AI 自动只是推荐采纳，不替代玩家操作。

### 5.2 手动操作顺序

**先选两个不同物理座位 → Resolver 根据当前座位动态过滤角色 → 如需下拉选角色 → 按钮带完整线索“展示给玩家：X号与Y号中有一位是角色名” → 私密全屏 → 返回可改 → 最终 Next。**

- 普通/特殊座位分别使用长/短虚线；所有不同座位原则上可点，不因无虚线而禁用。
- 先选两人；如果仅一个展示角色，直接选定，不加空下拉；无可用结果则禁用展示按钮，允许改选座位；改选座位后重新求值，原角色仍可用则保留，否则清空。
- 不单独增加“预览文字”；按钮就是预览。全屏返回后恢复人工或 AI 原选择，迟到的 AI 推荐不得抹掉人工草稿。
- 适配 5–15 人小竖屏；下拉必须**单列纵向**，允许分组标题但禁止右侧第二栏或每条反复写来源。

### 5.3 Pair 普通目标与特殊目标

| 角色 | 普通提示（金色长虚线） | 特殊提示（青色短虚线） |
| --- | --- | --- |
| 洗衣妇 Washerwoman | 真实镇民座位 | 相关且能力有效的间谍可登记为镇民 |
| 图书管理员 Librarian | 真实外来者座位（包括实际 Drunk/隐士） | 相关且能力有效的间谍可登记为外来者 |
| 调查员 Investigator | 真实爪牙座位（间谍本身是爪牙） | 相关且能力有效的隐士可登记为爪牙 |

“相关”指**当前已选两座位中确实包含该特殊目标**，或绘制未选座位候选提示时该座位本身为相关候选；不能因别处有 Spy/Recluse 就把所有角色全部放开。

### 5.4 下拉范围及来源区分（产品短名单）

| 信息能力 | 正常工作且无相关有效特殊登记 | 信息能力 Drunk/poisoned，或所选两座位包含相关有效特殊登记 |
| --- | --- | --- |
| 洗衣妇 | 所选两人中能正确登记为镇民的实际角色 | **实际在场镇民 + 已确认三个恶魔伪装中属于镇民的角色** |
| 图书管理员 | 所选两人中能正确登记为外来者的角色 | **当前剧本全部外来者** |
| 调查员 | 所选两人中能正确登记为爪牙的角色 | **当前剧本全部爪牙** |

- 洗衣妇下拉 **仅两块纵向分区**：“在场角色”“恶魔伪装”；分区即来源，不在选项右方再增加“在场/伪装”列或标签；角色名去重。正常只有少量选项时不强行放分组标题。
- 恶魔伪装只用 **Session 已确认 `demonBluffRoleIds`**；仅有两个镇民伪装则只加入这两个。5/6 人若无此已确认列表，不凭空补造三个。真实在场不以酒鬼的 `shownRole` 代替 `actualRole`。
- 这里是为了给恶魔玩家更多伪装空间而确定的**UI 实用候选范围**，不是官方规则的完整列举；例如间谍登记可能允许其他未在场角色，但默认不提供一整张长列表。后续如需高级模式另行批准，本批不做。
- 图书管理员正常情况下没有外来者时，保留直接“0/没有外来者”展示；如有效间谍登记导致可能存在其他结果，不强制只有 0。调查员所选座位不具爪牙或有效隐士登记时，下拉空、展示按钮禁用；不随便添加“0 爪牙”假结论。
- **防无解**：源能力 Drunk/poisoned 且实用短名单为空时，不得卡死该夜步骤；仅针对当前类别增加最小的剧本类别兜底选项，仍不恢复全剧本无关角色列表。
- 选中角色更换、两个座位更换、醉毒时序变化、角色变化或 AI 过期时，重新读取 Session 并计算；上次预览失效规则不变。
