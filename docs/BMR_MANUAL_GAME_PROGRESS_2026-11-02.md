## 三项普卡用户裁定

1. 自选后自身持续中毒；前一晚目标解毒且不死亡；后夜仍选择但无效果。
2. 连续两夜选同一非自身目标，结算旧施毒记录，保留本夜新毒；旧死亡被保护也不清新毒。
3. 普卡行动时仍因侍臣醉酒，之后同夜侍臣被刺客杀死：当夜立即恢复旧毒并结算旧目标；不重复唤醒普卡，不增加选择。

这些是项目所有者已明确确认的边界，不冒称官方原文逐项覆盖。当前无待人工裁定问题。

## 架构与存档核对

- 唯一写入者仍是 `ClocktowerGameSession` / `ClocktowerSessionState`；目标域、有效结果、信息命题由 Session 提供，不另建 BMR GameState 或规则裁判。UI 当前仍有规则条件组合残留，详见上面的审查遗留；不能把“没有第二写入者”等同于“UI 职责已全部收拢”。
- 仍为原 AtomicFile 单活动局、Session JSON v1。旧存档缺少 `drunk` / `registeredDead` 默认 false，Execution 缺少 `died` 保留旧致死语义；新事实仍在原 actions 时间线。信息命题扩展仍使用现有语义 JSON schema 2。
- 只恢复最后一次成功确认的游戏状态；未确认选择/预览可重做。没有完整开局快照、历史存档槽、回放、导入导出、持久 UI 游标或通用恢复框架。
- 同批删除 `ClocktowerBmrOpeningTable` 及仅预览的提前返回路径、DEBUG 可用性门槛；无双套预览/真实游戏入口。删除生产文件 0、删除独占测试 0。相对普卡事实检查点 `f7f4772a`，生产 Kotlin 净增 112,850 字节（12 个新文件分担夜间、白天、信息和 UI 职责）；全仓生产 Kotlin 最大为 Session 的 47,116 字节，无文件超过 50,000 字节。
